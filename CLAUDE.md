# CLAUDE.md — общие правила фабрики

Эти правила действуют для всех агентов обоих проектов.

## Контекст проекта
- Активный проект определяется файлом `ACTIVE_PROJECT` в корне (`vernatun` | `fingrad`).
- Данные проекта берём только из `projects/<активный>/`: бренд (`brand/`), контент-план (`content-plan/`), черновики (`drafts/`).
- Никогда не смешивать данные двух проектов.

## Два контура работы и прозрачность ролей (жёсткое правило)
Фабрика работает двумя контурами — не путать:
- 🏭 **Работники контент-завода** — `projects/<проект>/.claude/agents/` (`content-director`, `scout`, `reel-lead`, …). Производят КОНТЕНТ (стратегия, планы, рилсы, карусели). Гейт — Редактор + апрув человека.
- 🛠 **Команда разработки веба** — `веб/.claude/agents/` + доктрина `веб/CLAUDE.md` (Оркестратор → Архитектор → Frontend/Motion/Backend/AI Bridge/Кодер → Тестировщик → Фиксер → Деплоер → **Клиент**). Пишет КОД веба.

**HARD, в ЛЮБОМ чате:**
1. **Прозрачность ролей — всегда.** По ходу помечай роль-меткой, какой агент сейчас действует (🔍 SCOUT, 🎯 ДИРЕКТОР, 🎨 FRONTEND, ⚙️ BACKEND, 🧑‍💼 КЛИЕНТ …) — в обоих контурах. Пользователь должен видеть, кто и каким инструментарием работает.
2. **Работа над кодом/вебом = контур разработки.** Действуешь командой по `веб/CLAUDE.md` и закрываешь ход блоком **`📋 ОТЧЁТ КОМАНДЫ`** (каждый участвовавший агент + Клиент построчно) с **вердиктом Клиента**; финал пользователю — словами Клиента после «согласовано».
3. **Работа контент-завода** (контент/планы) — контур работников; живая приёмка браузером не требуется, но роль-метки и короткий итог «кто что сделал» обязательны.

Правила подтягиваются автоматически: этот корневой `CLAUDE.md` — в любом чате; `веб/CLAUDE.md` и `веб/.claude/` — при работе под `веб/`. Если трогаешь код веба не из-под `веб/` — всё равно действуешь по доктрине разработки (прочитай `веб/CLAUDE.md`).

## Дизайн
- Единый источник стиля — `projects/<активный>/brand/design.md`.
- Любой визуальный шаг обязан использовать скилл `shared/skills/brand-kit`; стиль не хардкодить в агентах.

## Качество и публикация
- Ни один материал не уходит в соцсети/на сайт без: (1) прохождения Редактора, (2) явного апрува человека.
- Тон и запреты — из `projects/<активный>/brand/brief.md`.

## Хранение
- Тяжёлые медиа (видео/картинки/аудио) — во внешнем хранилище. В репозиторий кладём только ссылки/манифесты в `projects/<активный>/assets/`.
- Закончил значимый кусок → предложить `commit` + `push` (контейнер эфемерный).

## Память агентов и самоулучшение
- У каждого агента — свой файл памяти `projects/<активный>/memory/<агент>.md`.
- Агент перед работой читает **только свой** файл памяти (плюс бриф/дизайн). Чужую память не читает — так память не смешивается.
- «Самоулучшение» = текстовый лог уроков, не дообучение модели. Поймали косяк (человек/Редактор) → агент дописывает датированный урок в раздел «Выученные уроки» своего файла. В следующий раз читает его первым и не повторяет.
- Память проектов изолирована: `vernatun/memory/` и `fingrad/memory/` — разные.

## Эстафета сессий (STATE.md)
- Оркестратор при старте новой сессии читает `STATE.md` в корне, чтобы продолжить без потери контекста.
- Перед сменой сессии (например, ради нового коннектора) — обновить `STATE.md` и сделать `commit` + `push`. Тогда новый чат подхватит состояние.
- Коннекторы (MCP) вступают в силу на старте сессии; плагины-скиллы часто подхватываются на лету. Это норма, не потеря данных: агенты и память — в git.

## Переносимость
- Всё — обычные текстовые файлы. Не завязываться на абсолютные пути контейнера и на то, чего нет в git.
