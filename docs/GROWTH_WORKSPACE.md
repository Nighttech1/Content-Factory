# Ситуационный центр: серверные изменения и ручная очередь

Дата: 10.11.2026, Москва. Это руководство к новой рабочей доске `/growth`, не подтверждение её production-выкладки или настройки секретов.

## Экран и данные

Шесть этапов воронки фильтруют канбан и один недельный график. Канбан: Задача, Съёмка, Монтаж/Разработка, Согласование, Выпуск. Любую карточку можно перемещать в любой столбец, в том числе назад. Колонка «Выпуск» сама не подтверждает публикацию: для Факта нужны URL и реальная дата. План показывает все задания выбранного этапа, Факт — подтверждённые публикации.

Кнопка «Обновить данные» открывает редактирование текущего недельного факта после входа владельца. Значения — целые неотрицательные люди или пустое неизвестное. Пустое не равно нулю. Сохранение на сервере и backup в GitHub — отдельные подтверждения. Другой клиент/reload читает тот же серверный state, не localStorage. Конфликт версии требует перечитать данные, не затирать чужую правку.

Исходные 24 V-ID и брифы сохраняются. Пока происхождение/сценарий не проверены, карточка честно требует разведки. Предложенные AI-механики не выдаются за тренды. Окно карточки позволяет владельцу внести проверенные тему, сценарий, кадры, источник, решение отдела и proof публикации; это не автоматический выпуск в соцсети.

## Конфигурация сервера

| Переменная | Назначение |
|---|---|
| `GROWTH_ADMIN_SECRET` | Отдельный случайный секрет владельца длиной не менее 32 символов; вводится в защищённом окне платформы |
| `GROWTH_ALLOWED_ORIGIN` | Точный HTTPS origin сайта, без path: `https://content.vernatunspeakclub.com` |
| `GROWTH_WORKSPACE_DATA_DIR` | Необязательный абсолютный путь; по умолчанию `data/local/growth-workspace` относительно cwd приложения |
| `GROWTH_WORKSPACE_SCHEDULER` | `1` включает Node-only периодическую фиксацию недель и catch-up |
| `GROWTH_GITHUB_REPOSITORY` | `Nighttech1/Content-Factory` |
| `GROWTH_GITHUB_BRANCH` | Ветка backup: `codex/director-chatgpt-transfer` |
| `GROWTH_GITHUB_TOKEN` | Отдельный server-only GitHub token с доступом к нужному repo и Contents read/write |
| `GROWTH_SCOUT_BRANCH` | Ветка очереди: `codex/scout-handoff-20261109` |

Нужны реальные серверные переменные, не только одноимённые Actions Secrets. Чатовый GitHub-коннектор тоже не является runtime credentials. Не использовать SSH private key или ключ LLM как пароль/токен редактора. Значения не присылать в чат и не сохранять в репозиторий/логи. Пример содержит только имена и публичные параметры: `docs/GROWTH_WORKSPACE.env.example`.

На существующем VPS cwd `/opt/content-factory/current`, `data` уже указывает на постоянный `/var/lib/content-factory/data`; default state будет вне release bundle. Сервис `content-factory.service` должен иметь права записи в этот собственный каталог. Прежние env-настройки находятся в `/etc/content-factory/app.env`: при настройке добавлять только новые ключи, не заменять весь файл. Реальную настройку/перезапуск выполнять отдельно после разрешения владельца, с private backup прежнего env. Это руководство само ничего на VPS не меняет.

Если owner secret/origin отсутствуют, изменения заблокированы; локальный QA-переключатель OWNER не авторизация. Session — подписанная HttpOnly Secure SameSite Strict cookie, CSRF nonce и ограниченный срок. Введённый секрет не хранится в browser storage. UI не раскрывает секретные значения или приватные пути.

## Backup и сбои

Runtime state хранит агрегаты/карточки/события/снимки/очередь одной атомарной транзакцией с revision CAS и idempotency ID. Не удалять `state.json` для «исправления» ошибки. Повреждение/FS failure — блокер, не молчаливый reset.

После local commit outbox доставляет отдельный sanitized snapshot в `projects/vernatun/content-plan/workspace-history/<revision>.json`. Секреты, sessions и внутренние receipts в Git не отправляются. Чужие файлы/ветки не затираются force push.

- `not_configured`: серверное сохранение выполнено, GitHub не настроен; backup ещё нет.
- `pending`: доставка ожидается.
- `error`: доставка не подтверждена, данные/очередь остаются на сервере.
- `synced` и commit SHA: GitHub подтвердил сохранение.

Повтор доставки не должен создавать дубликат или терять более свежую правку. Configured не означает проверенный доступ: успешная запись подтверждается отдельно. Пропавшие права/сеть/лимит — честная ошибка, а не зелёная синхронизация.

## Недели

Неделя начинается в понедельник, граница — воскресенье 23:59:00 по Москве, часы сервера. Для закрытой недели сохраняется последнее измерение этой недели не позже cutoff; поздний текущий факт назад не копируется. Если замера нет — `null`, а не ноль/прошлое значение. Первоначальная freeze-версия immutable; исправление создаёт следующую версию с причиной и источником. График показывает последнюю редакцию выбранного этапа с разрывами неизвестного.

Для long-lived standalone scheduler включается отдельно переменной. После простоя catch-up восстанавливает снимки по датированным событиям; `capturedAt` может быть позже cutoff. Разовый ручной catch-up той же логики: `node --import tsx scripts/freeze-growth-workspace.ts` из `веб/` в source checkout с тем же постоянным storage. Наличие скрипта не означает настроенное расписание VPS. Статус scheduler показывается в параметрах синхронизации.

## Ручной Скаут

Кнопка «Обновить» сохраняет только запрос поиска замены. Git-путь: `projects/vernatun/departments/scout/requests/growth/<requestId>/00-request.json`, **в отдельной ветке Скаута**. Технический requestId не производственный V-ID и не S-ID отчёта. `queued/git_pending/git_saved` — статусы доставки, не выполнения исследования.

После подтверждённой Git-записи владелец вручную пишет в чат Скаута «обновляй инфу». Для нового маршрута подготовлены narrow intake addenda в START/README Scout branch; публикация и факт перечитывания чатом подтверждаются отдельно. До ручного сообщения никаких поисковых API, LLM, платных сборов или workflow dispatch не происходит. Старые разрешения/бюджеты других исследований не наследуются.

Скаут проверяет реальные первоисточники и дату/метрики/ограничения, сохраняет отчёт и адресный бриф отделу; не выдумывает его утверждение. **Автоматический импорт отчётов Git в карточки не входит в эту волну.** После проверки результаты вносятся владельцем в окно карточки; серверное сохранение работает без пересборки сайта. Контракт очереди: `projects/vernatun/departments/scout/requests/growth/README.md`.

## Проверка и выпуск

Нужны тесты auth/CSRF/origin/session expiry, two-client/reload/CAS/idempotency, filesystem/Git failures, weekly cutoff/correction/null и desktop/mobile UI. Настоящие network Git writes тестируются отдельно при разрешении, unit mocks не доказывают настроенный token на VPS. QA-only Actions использует одноразовые секрет/cert/storage и HTTPS loopback fixture, не production credentials.

Код → успешный QA/артефакт → независимый Клиент без открытых C-* → отдельное разрешение на production → `docs/DEPLOY.md`. Не менять release marker от одного сохранения этой документации.
