# Директорский план → GitHub → ситцентр

Разрешение владельца11.11.2026: подключить план и дальнейшие правки к работающему сайту. Единственная ветка — `codex/director-chatgpt-transfer`. Секреты не добавляются: repo публичный, сервер читает только фиксированный GitHub JSON, не исполняет удалённый код/HTML.

## Как обновлять

1. Директор меняет актуальные блоки месячных MD, брифы jobs и `projects/vernatun/content-plan/exports/publication-plan-2026-v3.json`. Для каждой единицы сохраняются ID, основной этап, продукт, каналы, дата публикации; для REL отдельная `shooting_date` — вторник/суббота, не позже публикации. Съёмка не означает готовность/выпуск. Подготовить сценарий до встречи, согласие людей в кадре отдельно.
2. Обновить полный `vernatun_publication_plan_2026.md`. Поднять `sequence` на1 и осмысленно обновить `revision` в JSON: даже маленькая содержательная корректировка получает новую редакцию. Не использовать timestamp как доказательство апрува.
3. Из корня: `node scripts/prepare-editorial-plan.mjs --sequence N`. Проверка сопоставляет каждую единицу с активной таблицей месячного canon, обновляет MD/HTML delivery и JSON bootstrap. Из `веб/`: `node --import tsx scripts/test-growth-editorial.ts`, `npx tsc --noEmit`.
4. Commit/push контентных файлов в указанную ветку. **Не менять QA/release markers ради обычной правки плана.** Не запускать сборку/перезапуск VPS ради данных.
5. На VPS долгоживущий Node runtime проверяет JSON примерно каждые60сек; браузер перечитывает рабочую область каждые15сек и при возврате в окно. Обычно новая версия видна за60–90сек; сеть/GitHub/остановленный процесс могут задержать доставку. Подтверждение — `/api/growth-workspace` → `editorial.status=synced`, нужные `plan.revision/sequence` и ID. Это не гарантия мгновенной доставки.

## Границы

- HTTP запрос фиксирован на public raw GitHub URL конкретного repo/branch/file; timeout8сек, redirects запрещены, максимум1.5MB. Нельзя задавать URL из браузера/плана, передавать токены или читать arbitrary file.
- Схема проверяет ID/даты/каналы/брифы, недельные суммы/форматы/80-20 первых6недель, съёмкиВт/Сб. Duplicate, fake publication URL, версия ниже текущей или изменённое содержимое под тем же sequence отклоняются.
- Последний корректный план сохраняется вне release bundle, рядом с постоянным workspace. Есть проверенный bundled bootstrap. Ошибка показывает `stale` и оставляет предыдущую рабочую версию. Некорректный state/journal не обнуляется.
- Карточки директора — план/task/pending/unverified. Они не получают чужое решение отдела, viral proof, approved Scout provenance или publication fact автоматически. Prepared Scout contract остаётся прежним и строгим.
- Плановые брифы, стратегия, типы/площадки, сериал, недельный объём, приёмы встреч, источники и handoff видны прямо в `/growth`; полный чат и секреты не переносятся.
- Runtime факты, история, публикационные ссылки, колонка/order и edits владельца не затираются планом. Конфликт содержательных правок виден; новая версия не подменяет сохранённый текст владельца. Пропавшая строка не удаляет state/историю. Старые неизменённые seed-заглушки скрыты, реальные изменения/публикации сохраняются.
- Применение идёт под существующим file lock с journal, backup и CAS. Старый state shape не меняется: rollback приложения не восстанавливает старую копию поверх новых фактов.
- `GROWTH_EDITORIAL_SYNC=0` отключает этот контур (legacy QA); `bundled` — изолированный QA без сети; по умолчанию включён. Эти режимы не открывают редактор и не меняют owner auth.
- Код/схема требуют обычный QA/artifact/release один раз. После установки обновляются только данные. Публикация в соцсети/запуск отделов/API не входят в синхронизацию.
