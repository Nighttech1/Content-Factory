# ARCHITECTURE.md — Контент-фабрика

> Обновлено: 2026-10-29
> Проекты: **Вернатун** (армянский разговорный клуб — строим первым) и **Финград Консалтинг** (клон команды).

---

## 1. Принципы

1. **Мозг = подписка Claude Code** (НЕ своя API-платформа). Фиксированная цена, лимиты подписки, без оплаты за токены.
2. **Всё переносимо** — агенты, скиллы, правила, план = обычные текстовые файлы в git. В любой момент можно перенести на VPS + API разных ИИ.
3. **Единый источник правды для стиля** — дизайн-токены живут в одном файле на проект, их читает общий скилл. Никаких копий → никакого дрейфа.
4. **Ничего не публикуется без апрува** — между генерацией и соцсетями всегда гейт (Редактор + человек).
5. **Два независимых проекта, одинаковая структура** — переключение тумблером, а не правкой агентов.

## 2. Три слоя (не путать)

| Слой | Что это | Где живёт |
|---|---|---|
| **Мозги** | инструкции агентов, скиллы, правила, контент-план, промпты | **git / GitHub** (лёгкий текст) |
| **Ассеты** | рилсы, видео, картинки, аудио | **объектное хранилище** (Cloudflare R2 / S3) или медиатека платформы |
| **Чаты** | диалог с агентами | **Claude Code** (`claude.ai/code` + приложение), кросс-девайс |

> В git — только мозги. Тяжёлое медиа туда не кладём (лимит файла 100 МБ). В репозитории по ассетам храним только **ссылки/манифесты**, не сами файлы.

## 4. Тумблер проектов

Два независимых проекта с одинаковой структурой, но своими агентами и данными.

- **Способ A (нативный):** открыл папку `projects/vernatun/` → Claude Code подхватил её `.claude/agents` и контекст.
- **Способ B (файл-указатель):** общие скиллы читают `ACTIVE_PROJECT` и знают, чей `design.md`/бренд брать.
- **Способ C (удобный, делаем на Фазе 10):** слэш-команда `/project vernatun` / `/project fingrad`.

Переключил тумблер → те же роли автоматически работают с данными и дизайном другого проекта.

## 5. Команда: роли, а не модули-силосы

**Агенты = функциональные роли** (общие, пишем один раз). **Модули = пайплайны-рецепты**, которые композируют этих специалистов.

### Роли (на проект)

| Агент | Роль |
|---|---|
| 🎯 Контент-директор | стратегия, владеет контент-планом |
| 🔍 Разведчик | тренды, инфоповоды, конкуренты |
| ✍️ Сценарист/Копирайтер | сценарии, тексты, статьи |
| 🎨 Арт-директор | визуальный концепт, промпты под генерацию |

## 6. Правило «скилл vs агент» (ключевое)

- Что должно быть **одинаковым** во всех форматах (дизайн-токены, лого, бренд-войс, вёрстка/композитинг) → **общий скилл** (`brand-kit`). Один источник правды, вызывают все.
- Что отличается **ремеслом** (жанр текста/визуала под формат) → **отдельный агент/под-роль**, можно под пайплайн (сценарист карусели ≠ сценарист рилса).

Дублирования нет: общее вынесено в скиллы, а не скопировано в агентов. Единый дизайн гарантирует скилл.

---

## 7. Единый дизайн

```
projects/<проект>/brand/design.md   ← цвета, шрифты, отступы, правила лого (на проект)
shared/skills/brand-kit/            ← скилл, читает design.md активного проекта
```

- Любой визуальный шаг **обязан** загрузить `brand-kit`.
- `brand-kit` детерминированно накладывает **лого и текст/HTML-вставки** (HTML/CSS/SVG → рендер) — ИИ-генерация этого надёжно не делает.
- Переключение тумблера автоматически меняет и дизайн.

---

## 8. Пример пайплайна (карусель) — вложенные под-роли

```
1. 🖊 Сценарист карусели   → весь текст слайдов ОДНИМ связным проходом (одна история)
2. 🎨 Арт-директор         → единый концепт + ОДИН промпт/стиль-спека на весь набор
3. 🖼 Генерация            → базовые картинки (Ideogram / Flux / GPT) в одном стиле
4. 🖌 Финиш-арт-директор    → лого + HTML/текст-вставки, сверка с design.md, QA (скилл brand-kit)
5. 🧐 Редактор             → финальный гейт → человеку на апрув
```

> Слайды — единым концептом, НЕ 10 независимыми генерациями (разъедутся по стилю).
> Субагенты = вложенные под-роли внутри пайплайна, не параллельные клоны и не силосы.

## 9. Технологический стек по возможностям

| Задача | Инструмент (черновой выбор) | Где выполняется |
|---|---|---|
| Генерация картинок | Ideogram / Flux / GPT-image | внешний сервис (API/веб) |
| Композитинг лого/текста | HTML/CSS/SVG → рендер (Satori/Playwright) | скилл `brand-kit`, локально в контейнере |
| Сборка видео | FFmpeg + Remotion | контейнер (предустановлен Chromium/Playwright) |
| Субтитры | Whisper | контейнер |
| Аватары (говорящая голова) | HeyGen-тип | внешний сервис |
| Голос/озвучка | ElevenLabs | внешний сервис |
| Публикация | агрегатор (Buffer/Metricool) + cron | контейнер → соцсети |
| Хранилище ассетов | Cloudflare R2 / S3 | внешнее |
| Статистика/дашборд | платформа проекта | внешнее |

> Решения по конкретным сервисам финализируем на соответствующих фазах (5–9).

## 10. Публикация и гейт апрува

```
Контент-план → пайплайн генерит → Редактор (авто-гейт) → ЧЕЛОВЕК (апрув) → Публикатор (по расписанию) → соцсети
                                                                                  ↓
                                                                        Аналитик ← статистика
```

Жёсткое правило (в `shared/rules/`): **ни один пост не уходит в соцсети без прохождения Редактора и явного апрува человека.**

## 11. Переносимость и риски

- **Подписка кончилась** → агенты встают (мозг отключён). Код в git цел → переносим на VPS, подключаем API разных ИИ.
- **Контейнер эфемерный** → всё, что не в git, теряется при засыпании. Правило: закончил кусок → `commit` + `push`.
- **Лимиты подписки** → при упоре агенты ставятся на паузу до сброса окна (не доп. счёт). Старт Max 5x ($100) → при частых паузах апгрейд до 20x.
- **Токены на вложенные под-роли** → чем больше под-ролей в пайплайне, тем дороже один артефакт. Балансируем на фазе сборки.
