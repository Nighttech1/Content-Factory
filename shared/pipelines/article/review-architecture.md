# Архитектура: агенты Клода ↔ веб на российском VPS (ревью/апрув статей)

## Проблема
- **Продюсер:** агенты Клода (облачные сессии) генерят статью.
- **Потребитель:** веб-платформа на **российском VPS** — там владелец смотрит статью (красиво, как Telegra.ph), апрувит или пишет замечания → назад агенту на доработку.
- Прямой коннект агент→VPS нежелателен: хрупко/геозависимо, VPS пришлось бы открывать наружу.

## Решение: нейтральный «облачный ящик» (drop) + VPS ТЯНЕТ сам
Развязываем producer и consumer через **нейтральное хранилище, доступное обеим сторонам** (S3/R2-совместимое, глобально доступно — напр. **Cloudflare R2**: достаётся и из облака Клода, и с российского VPS по HTTPS). Агенты только **пишут** в ящик; VPS только **тянет** (исходящие запросы — работают из РФ к Cloudflare). Никто не «стучится» на VPS.

```
Агент Клода (облако)                 Нейтральный ящик (R2/S3)              Веб на VPS (РФ)
───────────────────                  ─────────────────────                ────────────────
1. собрал статью (блоки) + картинки → articles/<id>/article.json (+img)
                                     ← 2. VPS ПОЛЛИТ ящик (pull) → в БД
                                                                          3. /articles: превью (как Telegra.ph)
                                                                             владелец: Approve / Замечания
                                     articles/<id>/verdict.json ←──────── 4. VPS пишет вердикт+замечания в ящик
5. агент поллит ящик → читает вердикт
   - замечания → дорабатывает → новая версия article.json → (цикл 2–4)
   - approve → Публикатор публикует (Telegra.ph / сайт / Дзен) из одобренной версии
```

**Почему так:**
- Агенты не нуждаются во входящем доступе к VPS; VPS — только исходящие (pull). Нет «Клод → .ru» прямого коннекта.
- Нейтральный ящик достаётся с обеих сторон (Cloudflare R2 глобально доступен и из РФ).
- Устойчиво: VPS офлайн — статьи копятся в ящике; поднялся — забрал.
- Картинки — в ящик (не в git), git остаётся крошечным (только текст, если нужен).

## Превью в вебе = как в Telegra.ph (один источник)
Статья хранится как **упорядоченные блоки** (h/p/img/video). И веб, и Telegra.ph рендерят из ОДНОГО источника → картинки внутри текста, одинаково красиво. В разделе `/articles` веба — та же читалка + кнопки **Approve / Замечания**.

## Контракт данных (в ящике)
- `articles/<id>/article.json` — `{ id, version, title, blocks:[...], images:[{id,url,alt}], meta, status }`. Пишет агент.
- `articles/<id>/images/*` — картинки (или прямые R2-URL в blocks). Пишет агент.
- `articles/<id>/verdict.json` — `{ status: approved|changes_requested, comments:[{block_id, text}], by, at }`. Пишет веб (VPS).
- Версионирование: новая доработка → `version++`, новый `article.json`; история ревью в `verdict.json`.

## Петля HITL (замечания → доработка)
`агент → article.json(v1) → веб-превью → замечания(verdict) → агент читает → article.json(v2) → … → approved → публикация.`
Гейт сохраняется: публикуется только `approved`.

## Варианты (если не хочешь отдельный ящик)
- **A (рекоменд.):** R2/S3 как ящик (чисто, устойчиво, геонезависимо). Текст можно дублировать в git, картинки — только в R2.
- **B:** git (GitHub) как ящик для ТЕКСТА (агенты уже пушат туда) + R2 для картинок; VPS делает `git pull` + тянет картинки. Минус: GitHub из РФ бывает нестабилен.
- **C (проще, менее устойчиво):** прямой агент→VPS HTTPS POST + VPS→агент через polling. Работает, если окружение агента разрешает `.ru` и VPS публичный. Для MVP ок, но хуже по устойчивости.

## Что нужно (владелец), минимум для варианта A
- Завести **R2/S3-бакет** (Cloudflare R2 — дёшево, глобально) + ключи доступа (в окружение агентов и на VPS).
- На VPS — поллер (cron): тянет новые `article.json` → в БД; пишет `verdict.json` при апруве/замечаниях.
- В вебе — экран `/articles`: рендер блоков (как Telegra.ph) + Approve/Замечания (команда разработки).
