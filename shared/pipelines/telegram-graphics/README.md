# Пайплайн графики Telegram: цитаты и анонсы

Этот отдел готовит статичные брендированные изображения для канала клуба:
**карточки с цитатами участников** и **анонсы встреч**. В существующем вебе уже
есть модуль `aesthetic-graphics` (Module 2), но его текущая реализация возвращает
mock SVG. Этот пайплайн использует его как целевой тип модуля, не объявляя кодовый
рендер и отправку в Telegram уже готовыми.

Владелец отдела — `telegram-graphics-lead`; обязательный скилл —
`shared/skills/telegram-graphics/SKILL.md`.

## Задания и статусы

- Код: `TGP` — `V-ГГГГММ-TGP-NN`.
- Тип содержимого внутри брифа: `quote-card` или `meeting-announcement`.
- Папка: `projects/vernatun/departments/telegram-graphics/jobs/<ID>/`.
- Тяжёлые оригиналы и PNG хранятся во внешней библиотеке с проверенным доступом;
  Git хранит brief, тексты, права/источник, статус и манифест.

## Этапы и gates

| Этап | Исполнитель-маска | Артефакт | Gate начальника |
|---|---|---|---|
| 1. Вход и проверка | `telegram-graphics-lead` / `quote-reviewer` | тип задания, аудитория, CTA, проверка точного текста/фактов и разрешения на цитату | ID и бриф полны; quote use разрешено, либо факты встречи подтверждены планом |
| 2. Текст | `telegram-graphics-lead` | `10-copy.md`: текст на изображении, caption и CTA | Никаких неподтверждённых цитат/данных; текст умещается и читаем |
| 3. Арт-дирекшен | `art-director` | `20-art-direction.md`: композиция, типографика, палитра, safe zones, фон | Соответствие `design.md`, задаче и формату Telegram |
| 4. Фон | `designer` (если нужен) | чистый фон/фото без букв и логотипа, источник и права | Фон принят арт-директором; генератору запрещено рисовать бренд-текст |
| 5. Обязательный HTML-бейк | `finish-art-director` | PNG/JPEG и `40-bake-manifest.md` | На каждом готовом изображении есть корректный векторный/растровый логотип клуба и точный редактируемый текст, наложенные HTML/CSS/SVG-слоем |
| 6. Визуальный QA | `art-director` | `50-art-qa.md` | Реальный экспорт просмотрен: логотип/текст, мобильная читаемость, дата/время, safe zones, контраст и обрезка проверены |
| 7. Редакторский gate | `editor` | `60-editor-verdict.md` | `ACCEPT` либо точные замечания с возвратом к нужной роли |
| 8. Планирование публикации | lead + владелец | `70-publication-manifest.json` | Дата/время и подпись заполнены; владелец явно одобрил итог для публикации; нет секретов |

Роли вызываются как отдельные профили, если текущий хост поддерживает настоящих
субагентов. Иначе lead проходит роли последовательно и не называет их независимой
проверкой. После каждой фазы показывает в чате этап, маску, решение gate,
замечания и текущий блокер.

## Варианты

### Цитата участника

Текст цитируется дословно, орфография/пунктуация исправляется только с согласия
автора. До публикации нужно разрешение участника на публикацию цитаты и способ
атрибуции (имя, имя без фамилии или анонимно). Сам факт посещения клуба не является
согласием на публикацию. Если разрешение не подтверждено, карточка не проходит
gate. Фото участника добавляется только по отдельному разрешению.

### Анонс встречи

Дата, время и часовой пояс, место/ссылка, формат, язык/уровень, цена/бесплатность,
наличие мест и CTA сверяются с актуальным подтверждённым источником. Lead не
выдумывает и не переносит реквизиты из старого анонса без повторной проверки.
Промпт не должен генерировать дату/текст/логотип внутри фона.

## Единый визуальный контракт

- По умолчанию 1080×1350 (4:5), PNG для мелкой типографики; JPEG допускается,
  когда это нужно для размера/совместимости и качество проверено.
- **На каждом финальном изображении логотип клуба обязателен и всегда накладывается
  отдельно на HTML/CSS/SVG-слое.** Не использовать генеративно нарисованный логотип.
- Текст карточки, армянские плашки, дата, место и CTA также HTML-слой: точные,
  редактируемые и проверяемые; фон/фото выдаются без текста и логотипов.
- Использовать `projects/vernatun/brand/design.md` через
  `shared/skills/brand-kit/SKILL.md`; не хардкодить цвета, шрифты и положение лого.
- Проверить фактический PNG на телефоне/уменьшенном масштабе и отдельно проверить
  все строки, переносы, армянские глифы и event data.

## Handoff боту

Плановая дата в content-plan — намерение, не доказательство включённого бота.
После редакторского `ACCEPT` и явного апрува владельца заполняется манифест
публикации. Плановый consumer должен забирать только одобренные задания с
`scheduledAt`, передавать фото через Telegram Bot API `sendPhoto`, сохранять
`telegramMessageId`/`publishedAt`, обрабатывать ошибки и дедуплицировать по
`contentId + assetVersion`. Telegram Bot API сам отложенную отправку не выполняет.

В репозитории сейчас описан Bot API и имеется расписание/слоты веба, но не найден
проверяемый consumer, который связывает их с `sendPhoto`. Поэтому данный файл
фиксирует контракт на интеграцию; автопубликация считается работающей только после
проверки конкретного бота, очереди, хранения медиа и сквозного теста в тестовом
канале. Токены и приватные/временные URL не включать в манифест.
