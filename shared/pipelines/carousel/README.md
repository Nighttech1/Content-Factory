# pipeline: carousel — отдел карусели (Фаза 4)

Карусель собирает НЕ один агент, а **отдел субагентов** по chain. Единый стиль гарантирует скилл `brand-kit` (читает `projects/<проект>/brand/design.md`), стиль не хардкодим в агентах. Рендер слайдов — **layered-html** (фон-картинка + HTML/CSS-слой поверх), лого и текст — только на HTML-слое (не вжигаются в генерацию). Выравнивание с вебом: см. веб-скиллы `carousel-json-contract`, `carousel-studio-handoff`, S57 layered.

## Отдел (роли и инструмент)
| Роль | Агент | Делает | Скиллы |
|---|---|---|---|
| ✍️ Сценарист карусели | `scriptwriter-carousel` | весь текст слайдов ОДНОЙ историей + подпись + intent визуала | `content-calendar`, `cta-ladder` |
| 🎨 Арт-директор | `art-director` | выбирает **тип карусели**, единый стиль-спек, промпты фонов (где и сколько), QA визуала | `brand-kit`, `design-system` |
| 🖼 Дизайнер | `designer` | исполняет генерацию фонов (gpt-image `gpt-5.4-image-2` / Ideogram / Flux) по промптам арт-дира | `brand-kit` |
| 🖌 Финиш-арт («бейк») | `finish-art-director` | HTML/CSS/SVG-слой: лого + текст-вставки + элементы поверх фона, композит, QA по `design.md` | `brand-kit` |
| 🧐 Редактор | `editor` | финальный гейт (тон/запреты/CTA) | `cta-ladder` |
| 👤 Человек | — | явный апрув | — |

## Порядок взаимодействия (chain)
1. **Сценарист карусели** → тексты слайдов (связная история: хук → мысли → CTA), подпись, хэштеги, intent визуала. → в `drafts/`.
2. **Арт-директор** читает текст, **выбирает ТИП карусели** (см. ниже), пишет **ОДИН** стиль-спек на весь набор + per-slide бриф: сколько фонов генерить и на каких слайдах, где safe-zone под текст/лого. → задание Дизайнеру (или сразу Финиш-арту для HTML-типов).
3. **Дизайнер** генерит фоны по промптам (единый стиль, без текста/лого в картинке). → арт-диру.
4. **Арт-директор QA фонов:** стиль консистентен? нет вшитого текста/логотипов? safe-zone ок? → `approve` или `re-prompt` (ограниченно, бюджет генераций фиксирован).
5. **Арт-директор → Финиш-арт («бейк»):** задание разложить на HTML-слое лого + текст-вставки + элементы (по `design.md`, через `brand-kit`), поверх утверждённых фонов.
6. **Финиш-арт** рендерит композит (HTML/CSS → Puppeteer/Satori, **1080×1350**), все слайды.
7. **Арт-директор QA композита:** сверка с `design.md` (цвета/шрифты/отступы/лого), safe-zone, следов стирания нет, единый стиль на всех слайдах → `approve`.
8. **Редактор** финальный гейт (тон, запреты, CTA, формат) → **апрув человека** → публикация (сейчас вручную; позже Публикатор, Фаза P).

> Слайды — единым концептом, НЕ 10 независимыми генерациями (разъедутся по стилю). Субагенты = вложенные под-роли внутри пайплайна, не параллельные клоны.

## Типы карусели (арт-директор выбирает под задачу)
- **A — Full-gen:** ВСЕ фоны генерятся (Дизайнер), Финиш-арт кладёт лого+текст HTML-слоем. Для атмосферных/культурных.
- **B — Hybrid (обложка+CTA ген, середина — HTML-motion):** генерятся только **1-й и последний** слайды (обложка/CTA), остальные — красивый **HTML + motion-анимация** (Финиш-арт/Motion кодом). Экономит генерации.
- **C — Full-HTML-motion:** вся карусель — **HTML/CSS/JS motion** (кодом), без генерации фонов. Для инфо/язык/списков («5 фраз», «10 слов»).
- **D — Web-input (фото владельца / из интернета):** владелец в **вебе** кидает в задание свои **реальные фото** ИЛИ картинки из интернета → они становятся фонами; арт-дир кадрирует/отбирает, Финиш-арт кладёт лого+текст. Генерации нет.
- **E — Real-photo (нужны реальные, не сгенерированные):** когда по смыслу нужны реальные фото (напр. конкретных мест в Москве) → **Арт-директор САМ находит фото в интернете** (с проверкой прав/источника: свободная лицензия/свои съёмки/с разрешения), Дизайнер не генерит. Источник и права — фиксировать в манифесте ассета.

> Motion (типы B/C): для IG карусель — статичные кадры, поэтому motion-слой **рендерится в PNG 1080×1350** (HTML→кадры); «живая» анимация остаётся в веб-превью / видео-версии карусели. Лого — всегда на HTML-слое, не в фоне.

## Приём задания из веба
Через веб-дашборд (`/studio`, модуль `carousel-engine`) владелец может: выбрать тип (A–E), **приложить свои фото или ссылки на картинки** (тип D), указать «нужны реальные фото места X» (тип E). Веб кладёт задание → отдел карусели отрабатывает тот же chain. Контракт задания — `carousel-json-contract` (веб).

## Что нужно (ключи/статус)
- Генерация картинок (типы A/B/D-обработка): ключ `OPENAI_API_KEY` (gpt-image) или Ideogram/Flux — ☐ ещё не в окружении (Фаза 4 блокер для реального запуска; пайплайн описан и готов).
- `design.md` проекта + скилл `brand-kit` — ☐ создать на Фазе 4 (сейчас их нет).
- Рендер HTML→PNG — Puppeteer/Chromium (в контейнере есть).

## Гейты
Арт-директор QA (фоны + композит) · Редактор (контент) · Человек (апрув). Без лого/стиля из `design.md` и без прохождения Редактора карусель не уходит.
