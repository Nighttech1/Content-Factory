# automation — расписание, триггеры и интеграция агентов ↔ веб

> Как агенты фабрики работают САМИ (по расписанию/триггерам) и как они «стучатся» в веб-сервер.
> Реальные cron-триггеры заводятся в сессии вызова агентов / на развёрнутом вебе (секреты и триггеры вступают на старте сессии).

## 1. Расписание агентов (кадансы)
| Агент | Каданс / триггер | Что делает |
|---|---|---|
| 🔍 `scout` — виральные рилсы | ежедневно | агрегаторы (sila.app) + тренды → идеи-задания директору |
| 🔍 `scout` — мониторинг своих | 2–3×/нед | YouTube (API есть) / IG-TikTok (Apify, ≤1–2 прогона/день) → цифры |
| 🔍 `scout` — конкуренты | 1×/нед | снапшот конкурентов (Apify, экономно) |
| 📊 `analyst` | еженедельно + большой ежемесячно | SIGNAL-метрики + воронка → отчёт директору |
| 🎯 `content-director` | ежемесячно (план) + еженедельная ревизия | план месяца / правки по отчёту аналитика |
| ✍️🎨🎬 пайплайны (carousel/reel/youtube/article) | **on-demand** по плану | производство единиц из контент-плана |
| 🧐 `editor` | on-demand (на каждый черновик) | гейт качества |

Принцип: разведка/аналитика — по расписанию (автономно); производство — по заданиям плана; публикация — после Редактора + апрува человека (гейт не автоматизируем).

## 2. Механизмы триггеров
- **Claude Code cloud scheduled tasks (триггеры):** фоновый prompt будит сессию агентов по cron (напр. «scout: собери виральные рилс-идеи» ежедневно). Заводятся в чате вызова агентов. Триггеры/секреты вступают на старте сессии.
- **Веб-планировщик:** в `веб/` есть `lib/analytics/scheduler.ts` (node-cron / BullMQ) — ежедневный ingest метрик (06:00 UTC) при `REDIS_URL` или `ANALYTICS_ENABLE_NODE_CRON=1`. Публикация по расписанию — когда построим Публикатора (Фаза P).
- **Apify-дисциплина:** ≤1–2 платных прогона/день, `resultsLimit ≤50`, снапшот (см. `shared/skills/scout-apify`).

## 3. Интеграция агенты ↔ веб-сервер
Веб-сервер (`веб/`) — витрина и хранилище; агенты «стучатся» в его HTTP-API. Базовый адрес — из окружения (`CONTENT_FACTORY_WEB_URL`), авторизация — токен из окружения (напр. `INGEST_SECRET` для метрик). Точки стыка:
| Поток | Куда | Эндпоинт (веб) |
|---|---|---|
| Директор публикует план/единицы | веб (доски) | через API студии/расписания (`/api/schedule/*`, модули) |
| Сценаристы/отделы кладут черновики | веб (drafts/модули) | `/api/modules/*`, `/api/studio/*` |
| Аналитик/ingest метрик | веб аналитика | `POST /api/analytics/ingest` (авторизация `INGEST_SECRET`) |
| Владелец общается с агентами | веб → агенты | чат-поверхности веба (`/marketing`, студия) + мост Agent SDK (отдельный этап) |

> Источник правды контента остаётся в git (планы/агенты/скиллы); веб рендерит и хранит оперативное состояние (БД). Медиа — во внешнем хранилище.

## 4. Что нужно для включения автономии (следующая сессия)
- Завести cron-триггеры в чате вызова агентов (scout ежедневно, analyst еженедельно).
- На развёрнутом вебе: `ANALYTICS_ENABLE_NODE_CRON=1` или `REDIS_URL` для ingest; `CONTENT_FACTORY_WEB_URL` + `INGEST_SECRET` в окружении агентов.
- Ключи площадок/генерации (OpenAI/Apify/ElevenLabs/site API) — чтобы производство и ingest реально работали.
