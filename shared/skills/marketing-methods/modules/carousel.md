## Метод

1. Из принятого брифа выделить одно обещание, аудиторию и нужное следующее действие.
2. Выбрать редакционную структуру по материалу: последовательность действий,
   разбор ошибки, сравнение реальных вариантов, история или доказательный разбор.
   Обосновать выбор содержанием; список не маскировать под историю без развития.
3. Разложить на цепочку: обложка обещает → каждый средний слайд продвигает мысль →
   обещанная польза раскрывается → один CTA. Число слайдов определяет задача,
   не универсальная цифра из внешнего руководства.
4. У каждого свайпа проверить самостоятельную мысль и связь со следующим.
   Закрыть интригу до CTA; не скрывать ответ искусственно ради пролистывания.
5. На каждом факте оставить источник; подпись не должна только дублировать обложку.
   Формулировки и рамки бренда брать из нашего брифа, не из чужого hook-примера.
6. Передать арт-директору смысл/порядок/референсы. Производственный тип A–E,
   визуальную систему, фоновые промпты и bake-task определяет арт-директор.

## Разделение ответственности и gate

- **scriptwriter-carousel:** связный `10-script.md` и intent визуала.
- **carousel-lead:** проверить выполнение обещания, источники, один CTA и вход
  арт-директору; сохранить все существующие art/editor gates.

Читаемость проверять на мобильном по фактическому композиту. Сохранения и досвайпы
измерять только доступным источником; их нет в публичных Apify-метриках по умолчанию.
