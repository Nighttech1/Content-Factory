# Скилл: публикация в Telegram (через наш бот)

Берём **существующий бот** клуба (он уже сидит в чате и канале). Нужно лишь: бот — **админ канала** с правом **«Публикация сообщений»**, и его токен в окружении.

## Требуется (владелец)
- `TELEGRAM_BOT_TOKEN` — токен текущего бота (из @BotFather → этот бот). Секрет, только в окружение, не в git.
- `TELEGRAM_CHANNEL_ID` — `@mosarmclub` (или числовой `-100…`).
- Бот добавлен **администратором** канала с правом постинга (разово, в настройках канала).

## Что умеет бот (надёжно)
- **Текст/анонс:** `sendMessage` (Markdown/HTML, кнопки-ссылки на бот/встречу/статью).
- **Фото/карусель-обложка:** `sendPhoto` / `sendMediaGroup` (альбом).
- **Видео/рилс в канал:** `sendVideo`.
- **Опрос/вовлечение:** `sendPoll`.
- **Отложенная публикация:** через наш планировщик (веб `scheduler.ts` / cron), Bot API сам «на будущее» не умеет — ставим время у себя.

Пример (текст с кнопкой):
```bash
curl -s "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/sendMessage" \
  -d "chat_id=$TELEGRAM_CHANNEL_ID" -d "parse_mode=HTML" \
  --data-urlencode "text=<b>Тема недели: Армянская кухня 🍽</b>%0AСегодня — 5 фраз, чтобы заказать по-армянски. Приходи на встречу в четверг." \
  --data-urlencode 'reply_markup={"inline_keyboard":[[{"text":"Записаться","url":"https://t.me/vernatunbot"}]]}'
```

## ⚠️ Что бот НЕ умеет
- **Stories в канал** — Bot API не постит истории каналов (методы историй — для бизнес-аккаунтов). Сторис: медиа готовим пайплайнами, **выкладывает человек** (или позже отдельное решение). В TG-план недели сторис помечаем «вручную».

## Гейт
Как и всё: перед публикацией — Редактор + **апрув человека**. Бот постит только одобренное.

## Недельный TG-план (связка с директором)
Директор задаёт **тему недели** → собирает TG-контент под неё (анонсы встреч, 1–2 «тёплых» поста, фраза дня, опрос, тизер рилса) → после апрува бот постит по расписанию. См. `content-director.md` → «Неделя одной темы».
