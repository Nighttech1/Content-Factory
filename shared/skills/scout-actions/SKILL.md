# Scout через GitHub Actions

Транспорт: `.github/workflows/scout-data.yml`, **Scout data (manual)**,
`Nighttech1/Content-Factory`. Secrets доступны только Actions, их значения в чат
не извлекаются. Поддерживаются `YOUTUBE_API_KEY`, `APIFY_TOKEN` либо
`APIFY_API_KEY`. Наличие ключа не доказывает его валидность/квоту.

**Статус 06.11.2026:** описанная доработка подготовлена локально. До применения
и сверки remote SHA не считать её установленной на GitHub. В прежнем ТЗ прямо
запрещён commit/push; разрешение расхода API само по себе этот запрет не снимает.

## Режимы и разрешение

| mode | Поведение |
|---|---|
| check | Только признаки наличия ключей, 0 запросов к провайдерам |
| youtube | 1–5 хэндлов, 1–12 видео на канал, максимум 50; до 3 list-запросов/канал, без search |
| instagram | До 7 профилей × 6 публикаций; свой mosarmclub добавляется в ту же пачку |
| tiktok | До 5 подтверждённых профилей × 6 видео; платные дополнения выключены |

Для сбора нужно явное задание владельца, ID `S-YYYYMM-<GEN|CAR|REL|ART|YTB>-NN`,
входы/период/бюджет и `authorization` строго `COLLECT <report_id>`. Не запускать
по одному лишь чтению инструкции. `apify_budget_usd`: 0.01–0.50 на платформу,
месячный потолок владельца $5. Нельзя дробить сбор на платные пробы и повторять
при ошибке. Старые приёмочные примеры в других скиллах не выполнять автоматически.

Для V-202611-GEN-01: всего два actor starts, по одному на Instagram/TikTok,
суммарно до $1 **включая ошибки**. Плановые caps IG $0.49, TikTok $0.50;
$0.01 оставлен для возможных операций чтения/хранения. Расход не обязан
достичь потолка. Если профили не подтверждены/нерелевантны, не запускать ради числа.

## Проверка расходов до actor POST

Коллектор читает authenticated `/users/me/limits`, `/users/me/usage/monthly` и
актуальные `pricingInfos` выбранного актора. Согласованные текущие месячные циклы
обязательны. Берётся больший из двух показателей расхода и меньший потолок
аккаунта/$5. Неизвестные поля, параллельные actor jobs, неподтверждённый тариф,
недостаточный остаток, минимум cap выше разрешённого или слишком дорогая базовая
выборка → остановка **до старта**. Это проверка текущего цикла Apify, не глобальная
блокировка сторонних процессов аккаунта и не настройка его Limits.

Ровно один POST `/acts/<actor>/runs`: `maxTotalChargeUsd`, timeout=180,
`restartOnError=false`. До POST пишется состояние «запрошен, не повторять»;
после ответа сразу сохраняется run ID. Дальше только GET данного run. Если cap
не подтвердился в options, отправляется abort без второго старта. После terminal
status — контрольное чтение через 10 секунд: Apify предупреждает о задержке
статистики/стоимости. Сохраняется reported usage и `actual_charge_usd` из run
metadata, это не счёт-фактура. Неизвестная стоимость остаётся null, не нулём.
Ошибка/пустая/частичная выдача не обнуляет списания и не вызывает повтор.

Workflow сериализует ручные запуски; `GITHUB_RUN_ATTEMPT>1` для Apify запрещён.
Новый dispatch того же report/platform автоматически не дедуплицируется:
оператор обязан проверить журнал перед каждым запуском и не делать второй старт.
Сбой после POST мог оставить работающий actor — сначала проверить сохранённый
run/консоль. Никакого retry-storm или снятия cap.

## Запуск и чтение результата

Проверить версию workflow/коллектора на default branch. Использовать доступный
GitHub-коннектор/авторизованный `gh workflow run scout-data.yml` с безопасными
аргументами. Передать mode, report_id, handles через запятую, limit, authorization,
бюджет. Сбор сам не коммитит, не деплоит, не публикует и не пишет в веб. Cron нет.
GitHub Actions минуты/артефакты зависят от плана аккаунта.

После завершения получить run ID/attempt/status, jobs и artifact
`scout-<run_id>-<attempt>` (snapshot.json, хранение 30 дней). GitHub-инструменты:
`fetch_workflow_run_jobs`, `fetch_workflow_run_artifacts`, `download_workflow_artifact`.
Прямой CLI download ранее получал 403 Azure Blob; коннектор возвращал работающую
временную ссылку. Не выводить её в отчёт. Sediment download не применять к File
Service ID — ZIP читается по ссылке коннектора в `work/`.

Проверить report/repository/SHA/time UTC/run ID/attempt, status, source URLs,
выборку и стоимость. `presence_checked_not_authenticated` — не сбор;
`failed`/`partial` — не полная приёмка. Транспорт впервые проверен check-run
41809343795; наличие двух ключей — 41828149403 от 04.11.2026. Это не доказательство
валидности API. YouTube-run 42212889425 от 06.11 завершился ошибкой; не повторять
из этой записи.

## Анализ и выход

Наш IG отдельно `ours`, остальные `competitors`. Только публичные метрики,
недоступные значения null. Без reach/saves/демографии/конверсий и без прогнозов
прихода из просмотров. Возраст постов проверять по timestamp: сначала 90 дней,
при недоборе до 180 из той же выборки, без нового платного запуска. Сервисные
ошибки и отсутствие подходящих постов объяснять, чужие медиа не копировать.

Сырые снимки/ZIP — `work/`, не коммитить. Полный отчёт — `departments/scout/reports/`,
3–5 выводов директору; применимые адресные выжимки — `intelligence/` отделов.
Запись файла не подтверждает получения другим чатом. Передача ручная;
текстовый отчёт не объявлять отправленным в веб без проверенного отдельного API.

Локальная проверка без сетевых вызовов:
`python3 -m unittest discover -s shared/skills/scout-actions -p 'test_*.py' -v`.
