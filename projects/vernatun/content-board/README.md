# Доска контент-директора

Самостоятельная страница: `веб/public/content-board/index.html`.
Визуальные токены — из `projects/vernatun/brand/design.md` (brand-kit).
Основной font stack — Century Gothic; если его нет на устройстве, применяется
фолбэк. Лицензионный файл Century Gothic не включён в репозиторий. Нет CDN, внешних шрифтов,
библиотек, аналитических трекеров или запросов к AI.

## Что работает

- Доска: цели → гипотезы → эксперименты → результаты → решения.
- Создание и редактирование карточек, смена этапа, поиск, фильтр направлений.
- Календарь 70 материалов из черновика ноября, фильтр форматов, выбор дня.
  Структура плана одобрена 30.10.2026; даты требуют сверки с Google-таблицей.
  Комнаты `/campus` подтверждены, все 7 материалов о платформе активны.
- Локальное сохранение карточек в браузере, экспорт и импорт полной доски JSON.
- Адаптивный экран, клавиатурная навигация, режим reduced motion.

Результаты экспериментов, регистрации и охваты не выдуманы: таких данных пока нет.
Две начальные карточки решений взяты из брифа/памяти контент-директора.
Гипотезы являются предложениями, не одобренными экспериментами.

## Открытие и сохранение

Открыть HTML напрямую в браузере либо из корня репозитория:

```sh
python3 -m http.server 8081 --bind 127.0.0.1 --directory веб/public/content-board
```

В работающем Next.js файл также обслуживается как `/content-board/index.html`.
HTML можно скачать и передать без остальных файлов приложения.

Данные в localStorage принадлежат конкретному браузеру и origin. Файл,
локальный сервер и VPS имеют разные хранилища. Для переноса экспортировать JSON
и импортировать его на другом устройстве/адресе. При недоступном localStorage
страница сообщает об этом и позволяет экспорт. В этой версии нет серверной
синхронизации, общей записи несколькими людьми или API управления доской.
Для передачи изменений директору в чат нужно приложить экспорт JSON.

Снимок календаря обновляется из Markdown командой:

```sh
python3 projects/vernatun/content-board/refresh-calendar.py
```

Уже сохранённая браузером доска не перезаписывается новым снимком автоматически.
Календарь показывает план; изменение исходного Markdown или импорт JSON меняет
расписание. Публикаций и запусков пайплайнов при этом не происходит.

## Размещение на VPS

Существующий штатный путь — GitHub Actions `.github/workflows/deploy-vps.yml`
(ручной `workflow_dispatch`): Node 20 → standalone build → bundle с `public/` →
VPS `/opt/content-factory` → PM2 `content-factory` на 8088 → Nginx.
Целевой домен — `content.vernatunspeakclub.com`; `admin` не трогаем.
Доска попадает в тот же bundle как `/content-board/index.html`.
Этот путь не требует отдельного сервера или новых SSH-секретов.
Workflow использует существующие `INFINITYS_DOOR_VPS_*` в GitHub Secrets;
их готовность в этой сессии не проверена. Workflow не запускался.

Ниже — только запасной способ отдельной статической раздачи, он не применялся.
Копировать только `index.html` в каталог, обслуживаемый существующим HTTPS-сайтом,
например `/var/www/vernatun-board/index.html`. Команда копирования зависит от
утверждённого SSH-host и пути; доступ в текущей сессии не подтверждён.
Не публиковать весь checkout или файлы `.env`.

Для существующего Nginx server-блока пример маршрута:

```nginx
location = /content-board { return 302 /content-board/; }
location /content-board/ {
    alias /var/www/vernatun-board/;
    index index.html;
    add_header Cache-Control "no-cache";
}
```

Перед reload: `nginx -t`; после — проверить HTTPS-страницу в браузере.
HTML содержит внутренний черновик стратегии: разместить за существующей
авторизацией команды, если доска не предназначена для публичного доступа.
Развёртывание из текущей сессии пока не выполнено.
