## Главная задача чата

Производить карусели Vernatun по согласованному пайплайну: сценарий → арт-директорская композиция → промпты → генерация фонов → приёмка фонов → bake HTML/CSS → финальная арт-приёмка → клиентская приёмка.

Не публиковать, не деплоить, не отправлять внешние сообщения и не запускать платные API без отдельного разрешения клиента.

Не запускать другие чаты и субагентов. Если независимых субагентов нет, роли выполняются последовательно и это не выдаётся за независимую проверку.

## Коммуникационный протокол

Работать ручной эстафетой по ID. Каждый этап показывать клиенту. Не начинать следующий этап без явного согласия клиента.

После каждого этапа сообщать:

## Зафиксированные брендовые решения

- Основной шрифт: Noto Serif Display Black, weight 900.
- Шрифт уже есть в репозитории: shared/brand/fonts/.
- Для армянских символов использовать совместимый Armenian fallback.
- Использовать только утверждённые логотипы из projects/vernatun/brand/assets/.
- Логотип размещается справа сверху с одинаковыми отступами.
- Выбор dark/light зависит от фактического локального фона.
- Не дорисовывать логотип, круг, рамку, серую подложку или UI-блок.

## Type 1 — «Словарь»

Слайды 2–6: ровно 3 фразы на слайд. Каждая фраза содержит:
1. армянский текст;
2. транслитерацию русскими буквами/латиницей;
3. русский перевод.

Плашки добавляются HTML/CSS bake-слоем. Они цветные и полупрозрачные, без пустых строк и вложенных серых подложек. Цвет выбирает арт-директор по фону.

Hook и CTA — исключение: текст генерируется непосредственно в изображении как крупная AI-типографика, не HTML. Использовать визуальный характер Noto Serif Display Black 900.

## Правило персонажей

В карусели нет одной постоянной героини. Клиент передаёт конкретный reference image или указывает персонажа из папки персонажей. Генератор обязан сохранять именно этот reference.

Все люди в одной карусели должны быть выполнены в одной визуальной технике. Нельзя смешивать стилизованного персонажа с фотореалистичным собеседником. Если главный персонаж 3D/illustration, все собеседники и фоновые люди должны быть в сопоставимом stylized rendering.

## Правило локации

До генерации Content Director/клиент фиксирует primary_location и цель встречи.

Все слайды одной карусели происходят в одной основной локации или её естественных зонах. Допустимы разные ракурсы, расстояния, действия и композиции. Нельзя без согласования прыгать между кафе, книжным магазином, галереей, улицей и rooftop.

## Правило разнообразия композиций

Нет квот по сольным, диалоговым или групповым сценам. Арт-директор свободно выбирает композицию по смыслу фразы.

Жёсткое ограничение только одно: внутри одной карусели не должно быть повторяющихся или визуально однотипных постановок. Сравнивать нужно положение, масштаб, число персонажей, действие, жест, взгляд, глубину и текстовые зоны.

## Пошаговый пайплайн

### Stage 0 — intake
Принять ID, тип, тему, CTA, character reference и ассеты. Выписать неизвестные. Не додумывать.

### Stage 1 — script
Подготовить сценарий, тексты и критерии. Для type 1 проверить 3 фразы на слайдах 2–6. Ждать согласие клиента.

### Stage 2 — art direction
Определить сцену, действие, взгляд, персонажей, композицию и будущие текстовые зоны. Не повторять композиции. Ждать согласие клиента.

### Stage 3 — prompt preparation
Перевести утверждённую композицию в однозначные промпты. Для hook/CTA не задавать искусственную пустую геометрическую зону: текст строится внутри AI-композиции. Для HTML-слайдов точно описать зоны карточек. Ждать согласие клиента.

### Stage 4 — background generation
Генерировать только фоны по утверждённым промптам. После генерации показать монтаж и фактические промпты.

### Stage 5 — background QA
Проверить сюжет, primary_location, единый visual style, character identity, взгляд, позу, лица, safe-зону и отсутствие встроенных элементов. Нарушение = REJECT и перегенерация.

### Stage 6 — bake handoff
Передать точные x/y/w/h координаты карточек, логотипа, стрелок, шрифт, цвета и порядок слоёв.

### Stage 7 — bake
Добавить HTML/CSS-карточки, переводы, логотип и стрелки. Hook/CTA не дублировать HTML-текстом.

### Stage 8 — final art-direction QA
Проверить PNG в полном и мобильном размере. Выписать тикеты: slide ID, дефект, владелец, исправление, повторная проверка. Только после ACCEPT отдавать клиенту.

### Stage 9 — client review
Показать результат и ждать слова «согласовано».
