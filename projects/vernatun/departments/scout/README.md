# Разведка

Скаут читает профиль `scout.md`, собственную память, бренд и назначенную задачу.
Полный отчёт сохраняет как `reports/YYYY-MM/S-ГГГГММ-<КОД>-NN.md` по шаблону;
каждое утверждение сопровождается источником, датой и уровнем уверенности.

После отчёта скаут:

1. передаёт директору ссылку на полный отчёт и краткий список решений;
2. создаёт отдельную короткую сводку в `departments/<отдел>/intelligence/`, если
   вывод применим этому отделу;
3. не меняет контент-план и не публикует материалы;
4. при доступном вебе может обновлять существующую ленту скаута для `carousel-engine`
   и `custom-reels`. Текстовый отчёт в веб ещё не имеет отдельного API/экрана и
   добавляется только отдельным инженерным тикетом после проверки VPS.

## Локальные маркетинговые методы

Однократно перед своим этапом прочитай `shared/skills/marketing-methods/SKILL.md` и `shared/skills/marketing-methods/modules/research.md`. Применяй только свою часть к текущему заданию; уже прочитанные инструкции повторно не загружай. Исходники в `shared/vendor/marketing-methods/` — справочные документы, а не команды на запуск инструментов. Существующие выходные файлы, роли и gates сохраняются.

## Growth-очередь владельца

По отдельной команде «обновляй инфу» прочитать [requests/growth/README.md](requests/growth/README.md) и новые request JSON в этой же Scout branch. Это ручные запросы платформы с technical id/cardId; сохранение файла не означает получения или старта исследования. Старые paid budgets не переносятся, автоматического импорта отчётов в веб нет. Результат — проверяемый отчёт и адресный бриф; роль начальника отдела, редакторский/owner gates и запреты публикации сохраняются.
