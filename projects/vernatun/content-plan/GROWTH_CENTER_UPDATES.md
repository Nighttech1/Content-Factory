# Как обновлять «Центр роста» через чат

Версия 1 · 09.11.2026. Рабочая ветка — `codex/director-chatgpt-transfer`.

Сообщи директору «обнови дашборд» и передай только агрегаты или публичную ссылку на опубликованный материал. Агент проверяет данные и меняет общий источник; чат не записывает показатели в приложение напрямую.

## Что передавать

- **Встреча:** ID или точная дата, статус (проведена/отменена), записались, пришли, впервые/повторно, доступные места и расходы/выручка — только известные поля. Добавить источник и дату учёта. Отменённая встреча не означает ноль посетителей.
- **Этап воронки:** какой переход, период, ID/описание одной когорты, число уникальных людей, источник и дата замера. Просмотры отдельно от людей. Для возврата указать окно; 30-дневную когорту нельзя оценивать раньше её зрелости. Рекомендации и реактивация имеют свои базы сравнения.
- **Контент:** V-ID и реальный статус. Для «опубликовано» обязательны permalink и дата публикации; «готов», «одобрен», «в расписании» не означают «вышел».
- **Оценки:** прямо написать «моя оценка» и её период/ограничение. Нет числа — «нет замера», не ноль. Цель передаётся как цель, а не факт.

Не присылай имена/телефоны участников, выгрузки контактов, ключи, токены или иные персональные данные. Для сводки достаточно обезличенных итогов; массивы участников в общий dataset не добавляются. Пропущенные показатели агент не восстанавливает из фото, слов «всё отлично» или числа подписчиков.

## Два коротких примера

Это шаблоны формулировок, **не сведения о состоявшихся событиях**:

> Обнови дашборд: встреча [дата], пришли [N], впервые [A], повторно [B]. Факт по моему учёту на [дата].

> Обнови дашборд: [V-ID] опубликован [дата]. Ссылка: [permalink]. Остальные показатели пока без замера.

## Как изменение попадёт на все экраны

1. Агент читает текущую версию и сверяет ID, период/когорту, источник, единицы и статус доказательства. Уточняет только неоднозначность, способную исказить факт.
2. Меняет **только нужные поля** в каноническом [`веб/data/growth/vernatun.json`](https://github.com/Nighttech1/Content-Factory/blob/codex/director-chatgpt-transfer/веб/data/growth/vernatun.json), контракт `version: 2`; обновляет revision/updatedAt. Брифы `jobs/<V-ID>/00-brief.md` остаются исходниками производственных заданий, JSON — их индекс и операционные агрегаты.
3. Запускает строгую проверку схемы/ссылок/дат/публикационных доказательств и применимые тесты, показывает краткое изменение план/факт. Ошибку не маскирует удалением валидации или подстановкой нулей.
4. Сохраняет проверенную Git-ревизию, выполняет QA/build и **только разрешённый владельцем release** на `content.vernatunspeakclub.com`. `admin.vernatunspeakclub.com` не обновляется. Если разрешения или QA нет — изменение остаётся подготовленным, не объявляется доступным всем.
5. Проверяет `/growth` и read-only `/api/growth-center`, их revision и показатели. Только после успешного release сообщает «обновлено для всех»; пользователи увидят новую версию после загрузки/обновления страницы. Сохранение файла или commit сами по себе не обновляют работающий сайт.

В этой реализации JSON включается в сборку: live sync и запись фактов моделью через API отсутствуют. Нет публичного write API, автоматического парсера команд из чата или переноса browser-local значений старого `/marketing` в общую истину. Legacy `version: 1` с `attraction` не мигрирует молча в `version: 2` с раздельными `awareness`/`desire`.

## Что вернёт агент

Коротко: какие данные изменены, источник/период, новая revision, какие проверки прошли, статус release и что осталось неизвестным. «Приняла вводные», «сохранено», «проверено», «выложено» и «видно на сайте» — разные состояния.
