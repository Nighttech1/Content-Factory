# content-plan/ — контент-план Вернатуна

Здесь живут месячные планы, которые выдаёт **Контент-директор**. Из них команда (пайплайны) берёт задания.

## Правила
- Один файл на месяц: `ГГГГ-ММ.md` (например `2026-11.md`), по шаблону `_TEMPLATE.md`.
- Каждая единица контента имеет уникальный ID с кодом отдела и прослеживается к KPI «люди на живых встречах».
- Статусы единицы: `план` → `в работе` → `на апрув` → `одобрено` → `опубликовано`.

## Поля единицы
| Поле | Что это |
|---|---|
| ID | `V-ГГГГММ-<КОД>-NN`, например `V-202611-CAR-01` |
| Столп | один из 5 (встречи / комьюнити / язык / культура / платформа) |
| Формат | карусель / рилс / youtube / статья |
| Канал | IG / TG / TikTok / YouTube / сайт |
| Тема | рабочая формулировка |
| CTA | конкретный призыв (на встречу / в TG / в комнаты) |
| Дата | неделя или дата выхода |
| Статус | см. выше |

## Связь с встречами
Под каждую живую встречу (~5/мес) директор собирает кластер: тизер → анонс → напоминание → рекап.

## Коды отделов

| Код | Отдел | Рабочая папка |
|---|---|---|
| `CAR` | карусели | `departments/carousel/jobs/<ID>/` |
| `REL` | рилсы | `departments/reel/jobs/<ID>/` |
| `ART` | статьи | `departments/article/jobs/<ID>/` |
| `YTB` | YouTube | `departments/youtube/jobs/<ID>/` |
| `TGP` | Telegram-графика: цитаты участников и анонсы встреч | `departments/telegram-graphics/jobs/<ID>/` |
| `MST` | мультсторис, после создания отдела | `departments/multistory/jobs/<ID>/` |
| `GEN` | общая маркетинговая разведка, скаут | `departments/scout/jobs/<ID>/` |
| `STR` | стратегия и координация, директор | `departments/director/jobs/<ID>/` |

`GEN` и `STR` — служебные задания, не единицы выпуска; в объём 70 материалов не входят.
Отчёт по исследовательскому заданию имеет отдельный свободный ID
`S-ГГГГММ-GEN-NN` (номер не обязан совпадать с V-ID) и хранится в `departments/scout/reports/ГГГГ-ММ/`.

Директор создаёт папку задания в отделе и заполняет `00-brief.md` до передачи ID
лиду. Месячный план хранит только плановую строку и ссылку на папку задания;
рабочие документы не дублируются в нескольких местах.

Старые ID в утверждённых планах не переименяются. Новый формат действует для всех
новых заданий.
