# web-analytics-spec.md — приёмка и C-тикеты по веб-аналитике (/analytics)

> От Клиента команде разработки веба. Основано на read-only инспекции кода `веб/` (без запуска приложения).
> **Вердикт Клиента: ❌ НЕ ПРИНЯТО** — видимая страница аналитики полностью на моках; реальный бэкенд есть, но не подключён к экрану; нет бизнес-KPI (встречи/воронка).

## Что по факту (инспекция кода)
- Видимая `/analytics` рендерит **только мок**: `AnalyticsShell` берёт всё из `lib/analytics/self-learning-mock.ts` (хардкод), без fetch/store. `/analytics/page.tsx` — редирект на studio-версию, тоже на моках.
- **Реальный пайплайн существует, но «осиротел»:** Prisma/fallback store → адаптеры площадок → ingest → `aggregate-for-analyst` → Analyst-LLM → API-роуты (`/api/analytics/*`) работают, НО компоненты, которые их потребляют (`InsightsFeed`, `PublishedPostsTable`), **нигде не смонтированы**. Смонтированные `RetentionChart`/`RlFeed` получают мок-пропсы, не API.
- **Два несовместимых набора типов:** `lib/analytics-mock.ts` (питает API/store/осиротевшие компоненты) vs `types/analytics.ts` (питает отрисовываемый shell). Не связаны.
- **Адаптеры:** только YouTube + Instagram; **у TikTok адаптера нет** (хотя TikTok по всему UI). **Apify в аналитику не подаётся вообще.** YouTube/IG кривая удержания — **хардкод-фикстуры**; YouTube saves всегда 0.
- **Нет бизнес-KPI:** ни посещаемости встреч, ни лидов/заявок, ни воронки — только vanity (просмотры/сохранения/охваты/удержание). «Conversion Yield» есть лишь в seed-моке осиротевшего пути, и `aggregate-for-analyst` честно помечает это «seed gap fill».
- `aggregate-for-analyst` **выдаёт нормальную структуру** для внешнего Аналитика (`AnalystAggregatesPayload`), но богата она лишь настолько, насколько полон `PostAnalytics` (пусто → моки).

## C-тикеты (приоритет)
- **C-A1 (P0):** Подключить реальный путь к экрану — смонтировать `InsightsFeed` + `PublishedPostsTable` в `AnalyticsShell`/`AnalyticsMainGrid`, кормить `RetentionChart`/`RlFeed` из store/API, а не мок-пропсами. Свести два набора типов к одному.
- **C-A2 (P0):** Бизнес-KPI «люди на встречах» + воронка — добавить метрику и источник (клики бот/регистрация, заходы `/campus`), чтобы дашборд отвечал на KPI №1, а не только vanity. (Согласовать с Аналитиком, `projects/vernatun/.claude/agents/analyst.md`.)
- **C-A3 (P1):** Реальное удержание вместо хардкода (`youtube-analytics.ts`, `instagram-graph.ts`) — через YouTube **Analytics** API (не Data) / IG insights; YouTube saves ≠ 0 где возможно.
- **C-A4 (P1):** TikTok-адаптер (`adapters/index.ts`) — UI показывает TikTok, данных нет.
- **C-A5 (P2):** Подача Apify-снапшотов конкурентов/трендов в аналитику (или честно развести «свои метрики» vs «разведка»).
- **C-A6 (P2):** Убрать плейсхолдеры с «боевого» вида: `picsum.photos` превью, статичные «Razborщик summary», «Model Loss Convergence 94%», RL «Согласовано (мок)».
- **C-A7 (P1, безопасность):** ingest-эндпоинт открыт без `INGEST_SECRET` вне prod — закрыть перед выкладкой.

## Приёмка (DoD)
`/analytics` показывает **реальные** цифры из `PostAnalytics` (хотя бы YouTube — ключ есть) + бизнес-KPI «встречи/воронка»; мок остаётся только явным fallback при пустых данных; живой прогон Клиента @1440 на запущенном приложении (БД/Redis) без P0/P1.

> Реализацию ведёт команда разработки (`веб/CLAUDE.md`). Это требования Клиента, не реализация.
