# web-board-spec.md — ТЗ: доски Контент-директора в вебе

> От Контент-директора команде разработки веба (`веб/`). Что должно появиться на поверхности `/marketing`.
> Источник правды данных — контент-план (`projects/vernatun/content-plan/ГГГГ-ММ.md` + БД веба). Доски — это **виды** одного плана, не новая правда.
> Исполнение — по процессу `веб/CLAUDE.md` (Тренер → Архитектор → chain → Клиент). Это требования, не реализация.

## Контекст
- Поверхность директора `/marketing` (`веб/components/marketing/MarketingDirectorClient.tsx`) сейчас — только чат (Haiku). Нужно добавить к ней переключатель видов: **Чат · Таблица · Календарь · Контент-блоки**.
- Месячный календарь уже есть: `веб/components/schedule/ScheduleCalendar.tsx` (месячная сетка, drag-drop, редактор времени/площадки, модель `ScheduleSlot`). **Переиспользовать его**, не писать второй календарь.
- Модель данных (Prisma): `ContentJob`, `Draft`, `Board`, `ScheduleSlot`, `DesignSlot`. Единице плана соответствует запись (ContentJob/Draft + ScheduleSlot для даты).

## Поле единицы контента (минимум, для всех видов)
`id · столп (встречи/комьюнити/язык/культура/платформа) · формат (карусель/рилс/youtube/статья) · канал · тема · CTA · дата · статус`.
Статус-пайплайн единицы: `План → Сценарий → Дизайн/Монтаж → Редактор → Апрув → Опубликовано` (маппинг на `ContentJob.status` + `ScheduleSlotStatus`).

## 1. Таблица (список) — фильтры + сортировка  🔴 главное
- Вид «Таблица» — список всех единиц месяца.
- **Фильтры** (комбинируются): по **столпу**, **формату**, **каналу**, **статусу**. Плюс поиск по теме.
- **Сортировка** кликом по заголовкам: по **дате**, **столпу**, **формату**, **статусу** (возр./убыв.).
- Строка кликабельна → карточка единицы (тема, CTA, бриф, связанный Draft/ContentJob).
- UI — по `content-factory-ui` (Dark Luxury токены), таблица не «сток» (см. `frontend.md` HARD про 21st).

## 2. Месячный календарь — плашки в днях
- Вид «Календарь» на `/marketing` — **reuse `ScheduleCalendar`**: единицы плана как **плашки в днях** (цвет плашки = столп).
- Клик по плашке → та же карточка единицы; drag-drop переноса даты — как в `/schedule`.
- Сетка Mon-start, навигация по месяцам уже реализована — не дублировать.

## 3. Контент-блоки (пайплайн) — столбцы ПО ВИДАМ КОНТЕНТА
- Канбан, где **столбцы = виды контента**: **Карусель · Рилс · YouTube · Статья** (НЕ стадии план/сценарий/дизайн).
- Карточка = единица плана; в карточке виден её статус-пайплайн (бейдж) и кнопка «передать в работу».
- Назначение: **Публицист/Сценарист заполняет** карточки своего столбца (тексты/сценарии) при вызове в облачном чате вызова агентов. То есть столбец вида контента = рабочая очередь по формату.
- dnd-kit уже в проекте (используется в `/schedule`) — переиспользовать для перетаскивания карточек.

## Доступ
- Контент-директор имеет доступ ко всему вебу (чтение дерева; владение данными плана/досок). Вёрстку/инженерию делает команда разработки.

## Приёмка (Definition of Done)
- На `/marketing` переключаются 4 вида (Чат/Таблица/Календарь/Контент-блоки) на одних данных плана.
- Таблица реально фильтрует и сортирует (живой прогон Клиента @1440).
- Календарь — тот же `ScheduleCalendar`, плашки единиц в днях.
- Пайплайн-столбцы именно по видам контента; карточка открывается на заполнение.
- Ничего не публикуется в соцсети без Редактора и апрува человека (гейт HITL сохранён).
