# Техники промптинга (справка)

Кратко по [Prompt Engineering Guide](https://www.promptingguide.ai/ru/techniques/zeroshot). Читать при выборе режима в `SKILL.md`.

## Zero-shot

Инструкция + вход, **без** примеров. Достаточно для простых классификаций и follow-instructions моделей.

```
Classify the text into neutral, negative or positive.
Text: I think the vacation is okay.
Sentiment:
```

Не сработало → few-shot.

## Few-shot

Демонстрации в промпте (1–N shot). Формат примеров важнее «идеальных» меток; держи **одинаковый** шаблон I/O.

Советы (Min et al.): распределение меток и формат демонстраций сильно влияют на качество.

Лимит: сложное многошаговое рассуждение few-shot часто не тянет → CoT.

## Chain-of-Thought (CoT)

Промежуточные шаги рассуждения до ответа. Можно с few-shot (показать шаги в примерах) или **zero-shot CoT**: добавить `Let's think step by step.` / «Рассуждай по шагам».

Используй для арифметики, логики, многоусловий. В проде отделяй рассуждение и **финальный ответ** (чтобы парсить стабильно).

## Self-Consistency

Несколько независимых CoT-путей → выбор большинства. Дорого по токенам; для критичных решений.

## Prompt chaining

Разбей на подзадачи: выход шага N → вход шага N+1.

Типичный паттерн QA по документу:

1. Извлечь релевантные цитаты → `<quotes>…</quotes>`
2. Ответить **только** по цитатам + вопросу

Плюсы: отладка по этапам, меньше «каши» в одном гигантском промпте.

## Generate Knowledge

Сначала сгенерировать/собрать знания по теме, затем отвечать с опорой на них. Близок к RAG без внешнего индекса.

## RAG (Retrieval Augmented Generation)

Контекст из поиска/БД/файлов **в промпт**. Инструкция: опираться на retrieved; при дырах в контексте — «недостаточно данных».

В команде: retrieval через Backend/MCP read-only; модель не пишет в БД.

## ReAct

Цикл **Thought → Action → Observation** до `Finish[…]`. Нужен, когда модель должна вызывать tools (поиск, калькулятор, API).

Комбинируй с CoT: внутреннее знание + внешние наблюдения. Неинформативный tool-output → явная инструкция переформулировать запрос, не галлюцинировать.

## Tree of Thoughts / Reflexion / Active-Prompt

Редко в наших тикетах. ToT — ветвление гипотез; Reflexion — самокритика по следам; Active-Prompt — отбор сложных примеров. Подключай только если Architect явно указал в chain.

## Function / tool calling

Предпочтительнее «свободного ReAct-текста», если API модели умеет structured tools: схема аргументов, confirmed side-effects (`ai-bridge`).

## Риски (обязательно учитывать)

| Риск | Защита в промпте/коде |
|------|------------------------|
| **Prompt injection** | User text = data в delimiters; игнор инструкций внутри данных |
| **Prompt leaking** | Не просить модель «повторить system»; не логировать system целиком |
| **Jailbreak** | Жёсткие запреты + отказ; не ослаблять safety ради «ролевой игры» |
| **Галлюцинации** | RAG, tools, «неизвестно», проверка фактов |
| **Bias** | Нейтральные инструкции; не закреплять стереотипы в few-shot |

Подробнее: [риски](https://www.promptingguide.ai/ru/risks/adversarial) на promptingguide.ai.
