# Шаг 0 — готовность команды к дашборду жизненного цикла

Дата: 09.11.2026. Ветка: `codex/director-chatgpt-transfer`.
Исполнитель: реальный субагент Тренер. Scope: аудит инструкций и предметных пробелов, без кода приложения, commit/push и деплоя.

## План хода

- Запрос владельца: исправить недостаточный холодный вход в стратегию, количественно описать рынок/сегменты и сделать рабочий dashboard стадий привлечения/жизненного цикла в существующем Content Factory.
- Режим: UI + явный контракт маркетинговых данных + усиление инструкций агентов.
- Сохранить существующий shell и интегрировать в текущий `/marketing` либо `/analytics`, не создавать второй продукт.
- Различать привлекательность опыта для холодной аудитории, ответ на барьер первого визита и фактическую конверсию.
- Не путать демографическую базу, доступный сегмент, сценарий достижения и измеренных покупателей.
- Архитектор задаёт спецификацию и path locks до специалистов; backend/AI Bridge/Frontend работают в раздельных файлах.
- Рекомендуемая цепочка: Тренер → Архитектор → Backend/data contract + AI Bridge/инструкции → Frontend → Тестировщик → Фиксер при дефектах → Деплоер localhost → Клиент live acceptance.

## Грейд: B — архитектуру можно начинать

Роли и необходимые узкие навыки присутствуют; обнаруженные пробелы закрываются явной спецификацией и краткими дополнениями инструкций в этой волне. Отдельный блокирующий риск для завершения UI-приёмки — доступность реального браузера. Наличие `.mcp.json` не подтверждает работающую возможность запуска браузера. В родительском ходе Chromium завершался ошибкой `socket() failed: Operation not permitted`; новый live-прогон нужно реально попробовать и зафиксировать результат, не заменять его DOM-заглушкой.

Команда готова к архитектуре/реализации: **да, при принятии нижеследующего входного контракта**. Готова объявить завершённую пользовательскую приёмку: **нет, до живого сценария**.

## Минимальные изменения навыков / правил

Не подключать новые платные MCP, RAG-сервисы, базы и расписания ради этой задачи. Не читать секреты.

1. **Маркетинговый метод:** узкое дополнение к `shared/skills/marketing-methods/modules/director.md` и `research.md`: рынок/сегменты/JTBD/позиционирование/конкурентная альтернатива/attraction-first/полный жизненный цикл/доказательства и бюджет теста. Директор использует принятые выводы, исследователь собирает факты — роли сохраняются.
2. **Аналитический метод:** дополнение к `modules/analytics.md`: события стадий, cohort windows, attribution, sources, `null != 0`, scenario != actual. Для dashboard — аддитивное уточнение `content-factory-analytics` о клубном lifecycle, без изменения прежних роликовых контрактов.
3. **AI Bridge:** привязать эти правила к фактическому prompt-builder/контексту используемого директора, если он есть в scope. Простое создание markdown не является внедрением поведения работающего агента. Если внешняя модель не вызывалась — так и зафиксировать.
4. **Frontend:** применить текущие Dark Luxury токены, Century Gothic (`--font-ui`) и доступные layout-примитивы. Brand content export и приложение имеют разные поверхности: не заменять app shell бежевой автономной HTML-доской. Текущую UI-поверхность открыть через существующую навигацию.
5. **Tester:** guards на неизвестное/нули/источники/периоды/когорты; проверка desktop/mobile и клавиатуры. Никаких «всё зелёное» по синтаксису вместо пользовательского сценария.

По ограничению задания Тренера здесь **не изменены** общие навыки и код. Перечень — конкретный контракт для Архитектора и AI Bridge; их исполнение нужно подтвердить diff/проверками. Создан только этот датированный отчёт.

## Критерии готовности волны

- Есть утверждённая Архитектором спецификация и chain с непересекающимися path locks.
- Dashboard встроен в существующую поверхность, прежние chat/analytics не ломаются.
- Холодное привлечение, интерес, запись, участие, возврат, членство, рекомендации/реактивация представлены как разные стадии, а не один post funnel.
- Источники, даты и типы доказательств видны; пустые значения не заменены демо-числами.
- На стадии есть не только KPI, но и понятное действие владельца/директора и связанный контент.
- Реальные маркетинговые знания применены к действующему входу агента либо честно отмечено, что это только инструкция.
- Применимые проверки пройдены и UI gate подтверждён живым сценарием; иначе он явно открыт.
