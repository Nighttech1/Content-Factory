# План: Vernatun Carousel Agent v2 — пайплайн A + одна карусель 4 слайда

**Волна:** `W-2026-10-21-vernatun-carousel-v2`  
**Источник ТЗ:** `TECHNICAL_SPEC_CAROUSEL_AGENT_v2.md`, `PROMPT_PACK_v2.md` (в этой же папке)  
**Текущий код:** `lib/studio/vernatun-carousel/*`  
**Цель волны:** обновить **режим A (HTML/CSS Layers)** под ТЗ v2, перевести текстовые роли на **одну оркестраторскую модель** `openai/gpt-5.4` (субагенты в одном контексте), картинки — **GPT Image**, в конце выпустить **1 карусель × 4 слайда** с пакетом артефактов.

---

## Как читать этот план (для человека без IT-фона)

Каждый шаг — это галочка `[ ]`.  
Шаг считается **закрытым**, только если выполнены **все критерии приёмки** под ним.  
Нельзя перескакивать: следующий шаг стартует после закрытия предыдущего.  
В конце каждой галочки ставим `[x]` и коротко пишем «факт» (что получилось / путь к файлу / jobId).

## Архитектурное решение (зафиксировано до кода)

| Решение | Выбор | Почему |
|--------|--------|--------|
| Режимы | Меняем **только пайплайн A** в этой волне; B не ломаем | Запрос: «изменить текущий пайплайн A» |
| Модель текста | **Одна** модель `openai/gpt-5.4` на весь цикл: сценарист → AD сценария → менеджер изображений → дизайнер → главный AD → супервизор | Один контекст; роли = системные промты/режимы внутри оркестратора |
| Модель картинок | `openai/gpt-5.4-image-2` (или текущий GPT Image slug проекта) | Только фото/визуал без текста в режиме A |
| Слои A | HTML/CSS: фото, текст, логотип, карточки, нумерация — **отдельные слои**; экспорт Playwright → PNG 1080×1350 | ТЗ §2 режим A |
| Размеры блоков | **Не жёсткие константы**; решает главный арт-директор этапа 5 | ТЗ §3.6, §7.5 |
| Циклы ремонта | Макс. **3**; blocker → `BLOCKED` / `BLOCKED_WITH_REMARKS`, не FINAL | ТЗ §6 этап 5 |
| Объём демо | **1 job**, **4 слайда**, mode=A | Запрос пользователя |

**Gap относительно текущего кода (что ломает приёмку v2 сегодня):**

1. `role-models.ts` — разные модели на роли (Claude + gpt-4o), а нужно единое `openai/gpt-5.4` для текста.  
2. Вызовы ролей — **отдельные** LLM-запросы без общего session-контекста.  
3. `PROMPT_DESIGNER_HTML` жёстко задаёт счётчик **34–40 px** — противоречит ТЗ v2.  
4. Контракты замечаний AD (`VernatunDefect`) уже ближе к v1; нужны поля v2: `observed_issue`, `recommended_change`, `acceptance_check`, severity.  
5. Манифест изображений не полностью совпадает с `ImageAsset` v2 (quality_status PASS/WARN/BLOCKED, transformations).  
6. Фиксированный `TEMPLATE_CYCLE` в `designer-html.ts` рискует «шаблонностью»; AD должен влиять на композицию/геометрию, а не только текст.

### Шаг 2. Единая оркестраторская модель + session-контекст

### Шаг 4. Режим A: дизайнер HTML/CSS + влияние AD на геометрию

- [ ] Сохранить принцип: каждый слайд = отдельный HTML, слои разделены.  
- [ ] Убрать/ослабить жёсткие CSS-константы нумерации там, где они мешают AD.  
- [ ] Добавить канал правок геометрии из `ArtDirectorFinding` → CSS/HTML (не только text repair):
  - размер/opacity/позиция нумерации;
  - ширина текстовой панели / карточек;
  - позиция логотипа;
  - при необходимости — смена template/composition_hint.
- [ ] Разнообразие композиций: соседние слайды не обязаны, но серия из 4 не должна быть «одним клоном».  
- [ ] Логотип — отдельный слой с alpha; текст не запекается в фото.

**Критерии приёмки шага 4**

1. Для 4 слайдов генерируются 4 HTML-файла + ассеты.  
2. В HTML можно найти отдельные узлы/слои: photo, text/panel, logo, pagination (или осознанное отсутствие pagination по решению AD).  
3. Repair loop умеет менять **не только текст**, но и хотя бы 2 геометрических параметра по finding.  
4. Нет размытого «шва» photo↔text как единственного решения (чёткий край или градиент **внутри** текстовой панели).

### Шаг 5. Менеджер изображений и quality gate (Mode A)

- [ ] Генерация фона: **чистая фотография без текста/лого/рамки**.  
- [ ] Оригиналы неизменяемы; производные с transform log + hash.  
- [ ] Первичный фильтр short side ≥ 720 px — только фильтр, не «качество OK».  
- [ ] Манифест пишется до сборки; повторная проверка после экспорта (хотя бы размер PNG + сверка путей).  
- [ ] Не использовать один и тот же фон на все слайды без явной причины в манифесте.

**Критерии приёмки шага 5**

1. `ASSET_MANIFEST.json` содержит по каждому фону: source, размеры, sha256, quality_status, transformations.  
2. Исходники генерации лежат отдельно от рабочих копий.  
3. На 4 слайдах — 4 осмысленных слота (допускается WARN с фиксацией причины).  
4. BLOCKED-актив блокирует FINAL соответствующего слайда/релиза.

## Definition of Done (релиз демо-карусели)

Релиз демо готов, если:

1. Сценарий получил APPROVED (или эквивалент в коде после AD этапа 3).  
2. Каждому слайду назначены изображения с манифестом (PASS или явно принятый WARN).  
3. Главный AD этапа 5 вынес вердикт по каждому слайду (findings или пустой список с can_finalize).  
4. Блокеры устранены **или** статус не FINAL.  
5. Повторный рендер прошёл авто-QA (при FINAL).  
6. Выданы PNG + HTML Mode A + манифест + QA-отчёт.  
7. В отчёте честно указаны ограничения визуальной проверки.
