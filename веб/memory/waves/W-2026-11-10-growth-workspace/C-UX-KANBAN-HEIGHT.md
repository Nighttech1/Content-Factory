# C-UX-KANBAN-HEIGHT — ограничить высоту доски и сохранить обзор динамики

Статус: **OPEN**. Приоритет: **P2**. Зона: Frontend, существующая доска `/growth`. Изменение scope — только layout/scroll текущих колонок, не данные/новый dashboard.

## Факт

Клиент самостоятельно осмотрела actual CI screenshot `workspace-failure.png`, run `42795772848`, source `c03f2d7dd9993cb12e31dcd00bcbd6740c82a1d8`, desktop1440. Шесть карточек в «Задаче» растягивают всю страницу примерно до2800px, соседние пустые колонки заканчиваются спустя несколько сотен пикселей, недельный график оказывается далеко внизу после всей стопки.

Это мешает совместному обзору этапа/работы/динамики. Для переноса нижней карточки в короткую соседнюю колонку приходится возвращаться к далеко расположенному drop target; график теряется за списком карточек. Проблема видна на реальных24заданиях, не на искусственной перегрузке.

## Ожидаемое поведение

- У доски разумно ограниченная responsive высота (на desktop не выше viewport); пять колонок одинаковой рабочей высоты с видимыми заголовками/drop targets.
- Карточки прокручиваются вертикально **внутри своей колонки**; последняя карточка доступна мышью/клавиатурой/на мобильном. Горизонтальный scroll доски сохраняется, документ по X не переполняется.
- Недельный график остаётся непосредственно после ограниченной доски и не вытесняется всей длиной списка.
- Не удалять/не прятать часть карточек и не менять числа для улучшения скриншота. DnD, селектор любого направления, модальное окно и сохранение продолжают работать.
