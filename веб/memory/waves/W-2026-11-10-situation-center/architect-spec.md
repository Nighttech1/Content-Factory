## Задача и границы

Продолжить готовый `/growth`, не переписывать его. Пятый пункт меню после Директора — **«Ситуационный центр»**; сохранить Студию, Расписание, Настройки и Директора с их маршрутами и данными. Видимая навигация desktop/mobile имеет все пять пунктов. Существующий dark shell не редизайнить, использовать текущие UI/brand tokens и Century Gothic. Сохранить read-only API, bundled shared JSON, графики, 24 производственных V-ID, их даты/статусы/brief links, старый `/marketing` и чат.

В этой волне нет production-деплоя, merge, платных API, изменения prompts/runtime, публичного write API, автосинхронизации из чата, выпуска контента и изменения тарифов. Выполнение user-requested UI в локальном репозитории разрешено. Если локальный браузер заблокирован средой, Оркестратор может доставить исходники в текущую ветку и изменить только QA marker `.github/releases/growth-center-qa.json` для существующего CI. Release marker `.github/releases/growth-center-release.json` не менять; production не запускать. До устранения SSH-блокера не обещать VPS release. Сохранённый прежний QA относится к прежнему source, не доказывает качество нового кода.

## Поведение

1. Основная воронка: **узнать → захотеть → записаться → прийти впервые → вернуться → подписка**. Рекомендации и реактивация — отдельные ветки. Клик/клавиатурная активация шага выбирает его и переводит к нижним данным этого этапа (если открыта другая вкладка — открывает «Путь участника»). Не терять глобальный режим План/Факт. Выбранный этап должен иметь доступное имя/состояние и видимый заголовок ниже; scroll при необходимости без принудительной анимации reduced-motion.
2. Нижние блоки показывают аудиторию, потребность (`job`), барьер, продукт, стратегию, следующее действие, план/факт/источник, привязанные реальные V-ID и историю выбранного этапа. Уже существующее поведение сохранить.
3. Добавить между профилем и производственными заданиями блок **«Контентные механики этапа»**: переключение типа (все/юмор/полезное/мини-сериал/другие, только применимые текущему этапу) и карточки идей. На каждой карточке: тип, название, потребность/барьер, зачем этот формат на этапе, конкретный пример и hook, формат/каналы, CTA, что измерять. Состояние — **«Идея · не в производстве»**, без даты выпуска, V-ID и ложного выполненного результата. Видимые идеи — гипотезы стратегии, не утверждённый production plan.
4. В Плане показывать предложенные идеи и существующие задания отдельными блоками. В Факте идеи **не становятся фактом**: блок даёт ясное пустое состояние «Реализация механик ещё не подтверждена; идеи доступны в Плане»; опубликованные V-ID остаются только с URL+датой. Не создавать условные нулевые KPI или выдуманные соответствия идеи конкретному брифу. Фильтр механики влияет только на идеи; реальные задания фильтруются только по существующим `stageIds`/product/search. При смене этапа фильтр механики сбрасывается в «Все», чтобы исключить ложный пустой экран.
5. На холодном этапе минимум три разных направления: добрый узнаваемый юмор, полезная карусель для сохранения/пересылки, мини-сериал для возвращения к следующему эпизоду. На каждом из остальных семи этапов минимум одна предметная механика. Добавить игровые/интерактивные форматы, живой опыт гостя, полезный маршрут первого визита, продолжение разговора, честное сравнение пакета, приглашение друга и возвращение после паузы. Цель юмора — релевантный интерес и дальнейший переход к реальной встрече, а не обманный кликбейт. Полезное не превращать в обещание курса с нуля; армянские фразы проверить перед производством, русскоязычные заготовки допустимы. Мини-сериал — предложение формата с единым героем, конфликтом, продолжением и 3–4 конкретными примерами эпизодов, не реально снятый сериал. Юмор не унижает людей за язык/происхождение, сохранения и просмотры не объявляются посетителями.

## Additive контракт Backend → Frontend

Выбор: поле в **том же** `data/growth/vernatun.json`, а не hardcode в компоненте/второй sidecar. Это сохраняет общий источник и экспорт/API, а optional default позволяет загрузить прежний v2 snapshot и synthetic fixture. Операционные измерения и 24 задания не меняются.

```ts
type ContentMechanic = {
  id: string; // отдельный namespace idea-*, не V-ID
  stageIds: StageId[];
  kind: 'humor'|'useful'|'series'|'interactive'|'trust'|'invitation';
  title: string;
  need: string;
  barrier: string;
  purpose: string;
  example: string;
  hook: string;
  format: string;
  channels: string[];
  cta: string;
  successMetric: string; // что измерить, без обещанного числа
  status: 'proposed';
  sourceId: string;
};
// strict schema: contentMechanics: z.array(mechanic).default([])
// exported type ContentMechanic, pure getStageContentMechanics(dataset, stageId)
```

Все строки непустые и bounded по текущему `text`, ID уникальны, stageIds непустые/уникальные из STAGE_IDS, sourceId должен существовать; status только proposed, unknown nested/top-level fields запрещены. Для прежнего JSON отсутствие массива → [], не ошибка. Источник новых идей: dated source с репо-ссылкой на `projects/vernatun/content-plan/SITUATION_CENTER_MECHANICS.md` (Backend создаёт краткое описание пожеланий/предложений, не публикационный план), 10.11.2026, limitation «Пожелания владельца + предложения команды; не измеренный эффект и не поручение производству». Добавить источник, `updatedAt=2026-11-10`, revision новой редакции. Не менять старые sources dates, counts, estimates, targets, content, history. Если записи многократно относятся к этапам, не умножать число jobs. UI выводит текст обычными React text nodes, без HTML-инъекции.

## Исправление семантики подписки

Текущий код расходится с новым заданным маршрутом: `parent.membership='attendance'`, `Ветка от 04`, пятая стрелка скрыта, последний шаг пунктирный. Изменить на **return → membership**, подпись шестого основного шага и непрерывную стрелку основного маршрута. `stage-membership.definition` уточнить: фактически оплатившие подписку/пакет **из повторных гостей той же когорты**, намерение не оплата. Текущие counts null сохраняются.

Проверить getConversion/getConversionSeries и затронутые guards: база membership — return, не attendance; несовместимая/неизмеренная/незрелая база → нет расчёта с причиной. Не обходить maturity/period gates для получения красивой цифры. Рекомендации всё ещё от return независимо от подписки; реактивация от eligible-dormant. Заменять старое ожидание теста можно только одновременно с новым содержательным guard, подтверждающим именно согласованный denominator.

## Приёмка

- Desktop 1440 и mobile 390/360: пять ссылок навигации, заголовок «Ситуационный центр», маршруты прежних страниц, отсутствие общего горизонтального переполнения.
- Выбор всех восьми стадий меняет заголовок/потребность/барьер, идеи и реальные задания; возвращение к awareness восстанавливает исходный блок. На content/source вкладке выбор шага открывает detail.
- Awareness содержит юмор/полезное/сериал; фильтр меняет только идеи и не счётчик 24 реальных материалов. Другие этапы не пустые по ошибке фильтра.
- План/Факт обратимы: в Факте proposed не выдаются за published. При fixture с реальной synthetic публикацией показывается только её V-ID/proof, production JSON не загрязняется.
- Источник/формат/CTA/метрика доступны для каждой идеи, идеи не имеют выдуманной даты/V-ID. Старые null/estimates/meetings и 24 jobs сохранены.
- Model guards: valid optional array; invalid stage/source/duplicate/id/status/extra fields rejected; membership denominator return. Existing 31 model/boundary guards и типизация не ослаблены.
- Build и живой браузер с консолью; графики встреч/переходов и существующий чат не сломаны. Root реально попробовала Chromium: launch блокируется `socket() EPERM` в process_singleton_posix. Допустим реальный браузерный прогон через существующий QA-only GitHub Actions и осмотр полученных screenshots/JSON; локальный launch не выдавать за PASS. Команда model guards в этой среде — `node --import tsx scripts/test-growth-center.ts`; `npx tsx` CLI имеет EPERM на pipe.
- Независимый Клиент создаёт C-* замечания и возвращает команде. Все тикеты закрываются с доказательством и повторной приёмкой **до передачи владельцу**. При внешнем блокере вердикт открытый, не фиктивное принятие.
