3. Директорские карточки добавляются как task/pending/unverified, не prepared approved. Approved Scout catalog остаётся неизменным. Runtime state schema остаётся читаемой прежним кодом. Отдельный journal/sidecar и backup позволяют atomic recovery; карточки, facts, snapshots, receipts, sessions, outbox, publication proof не сбрасываются. До merge lock/CAS, owner edits сохраняются и конфликт помечается. Удалённые из плана задания архивируются только в отображении, из state не удаляются; работа/факт остаются доступны. Колонка/order/publication не перезаписываются.
4. /growth показывает новые планы в текущем канбане, inline brief/съёмочную дату, недели/матрицу форматов/сериал/площадки/приёмы встреч/источники/передачу в раскрываемом разделе. Все данные рендерятся React text, без raw HTML. Факт по-прежнему требует publication URL+date, а не наличия плана. Не переносить chat logs, секреты или старые несогласованные идеи: только актуальные решения и брифы.
