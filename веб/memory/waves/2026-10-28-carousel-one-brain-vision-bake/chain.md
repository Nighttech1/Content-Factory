# chain.md — волна «Единая Sonnet-маска + vision→Бейк»

> Overlapping paths НЕ параллелим — всё в зоне оркестрации пайплайна. Тикеты строго 01→02→03.
> API картинок жжём только на финальной приёмке Клиента (1 контрольная генерация), с явного «да» пользователя.

## Порядок ролей

1. 🏗️ **Архитектор** — spec + path-lock (готово: `architect-spec.md`).
2. 🤖 **AI Bridge** — маски/промпты:
   - база `JobLlmSession` → Sonnet; все текст-маски через одну сессию/контекст (C-ONE-BRAIN-01);
   - новый промпт `vision_layout` (смотрит кадр → раскладка Бейку: анкеры/цвет/safe-zone) (C-VISION-LAYOUT-02);
   - контракт «замечания → ребейк HTML, не реген» (C-REMARKS-TO-BAKE-03).
3. ⚙️ **Backend** — оркестрация:
   - свести дубли (один script-AD, один final-AD) в `orchestrator.ts` ↔ `correct-pipeline-job.ts` (C-ONE-BRAIN-01);
   - вставить `vision_layout` между `prepareSlideImages` и бейком; `renderer.ts` принимает раскладку (C-VISION-LAYOUT-02);
   - findings → дешёвый ребейк; загейтить image-regen (C-REMARKS-TO-BAKE-03).
4. 🧪 **Тестировщик** — `npm run test:vernatun` + новые guards:
   - модели масок = Sonnet в `role-models.json`; один script-AD / один final-AD;
   - `vision_layout` присутствует на слайд; раскладка варьируется;
   - счётчик image-gen = число слайдов (нет регена при replay с замечаниями).
5. 🔧 **Фиксер** — до зелёного; архитектуру вне chain не менять; тесты не ослаблять.
6. 🚀 **Деплоер** — `next dev` localhost для приёмки.
7. 🧑‍💼 **Клиент** — живой прогон @1440 + **1 контрольная генерация** (с «да» пользователя): проверить все 6 шагов схемы на реальном кадре; naked-eye + зум плашек; вердикт.

## DEV budget
- Разработка/тесты — без генераций картинок (unit + статический аудит контракта).
- 1 контрольная генерация — только на шаге 7, после кода и с согласия пользователя (регенерация запрещена).
