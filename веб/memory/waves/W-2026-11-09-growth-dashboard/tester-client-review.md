# Независимая проверка Тестировщика / Клиента

Дата: 09.11.2026. Волна W-2026-11-09-growth-dashboard. Исполнитель: реально вызванный tester_client, не автор Backend/Frontend/AI Bridge.

## Критерии и сценарии приёмки

1. `/marketing` открывает встроенный dashboard; существующие чат и проекты доступны, данные чата не перезаписаны.
2. Cold-привлечение начинается с привлекательности реального опыта и людей; FAQ «можно одному» расположен на этапе интереса/записи. На каждой стадии видны продукт, JTBD, контент, действие/ответственный, метрика и следующее решение.
3. Восемь стадий различимы; рекомендации — ветка повторного опыта, реактивация — собственная неактивная когорта. Подписка не является обязательным предшественником рекомендации.
4. `null` показывает отсутствие замера, `0` — измеренный ноль. Перепись, оценки владельца, сценарии и actual различимы. Подписчики не суммируются как уникальные покупатели.
5. Выбор стадии/вкладки/фильтра меняет соответствующее содержание. Импорт валидирует структуру, поля, даты, целые неотрицательные числа и известные границы одной когорты; ошибочный импорт не заменяет прежний snapshot. Экспорт/локальное сохранение не объявлены CRM-синхронизацией.
6. Конверсии требуют положительного известного знаменателя и совместимого фактического замера. Возврат — только после календарного созревания. Нельзя получать «совместимые» проценты из противоречащих друг другу известных значений при `null` промежуточных шагах.
7. На рынке: широкая историческая демография отдельно от покупательского SAM; неизвестные фильтры — сценарий, ёмкость — ограничение, не прогноз. Сегменты JTBD и конкурентные альтернативы содержательны.
8. Реальный desktop 1440 и mobile 360/390: нет обрезки, кликабельные действия, доступность клавиатурой, reduced-motion, старый чат доступен. Browser gate нельзя закрыть по исходникам/SSR.

## Найденный дефект

### C-GROWTH-01-D1 · P1 · транзитивная несовместимость частичной когорты

Файл: `lib/marketing/growth-model.ts`, `parseGrowthSnapshot`.

При `evidenceKind=measured`, `attraction=10`, `interest=null`, `registration=null`, `attendance=100`, `membership=20` парсер вернул `ok:true`; `conversionRate(snapshot, 'membership')` вернула 0.2 и сообщение «Совместимые уникальные люди одной когорты». Известные 100 первых гостей не могут быть подмножеством известных 10 входящих людей этой же когорты. Проверка только непосредственных соседей пропускает нарушение из-за неизвестных промежуточных значений.

Воспроизведено независимо через `node --import tsx`, stdout наблюдался. Backend/root уведомлены. Исправление ожидается у владельца data path; tester код не меняет. Проверка должна обойти известные ancestry bounds для последовательности и веток; отсутствие промежуточного значения не отменяет известный верхний предел.

## Ограничения среды

- `tsx` CLI пытается создать UNIX IPC pipe и падает `EPERM`; уместная проверка TypeScript работает через штатный `node --import tsx` без CLI IPC.
- По доказательствам root: CUA localhost:3017 получил connection refused, Chromium в sandbox — AF_UNIX denied. `file://` CUA запрещён policy; обход не предпринимается.
- Поэтому live desktop/mobile, Lighthouse и визуальная пользовательская приёмка пока НЕ выполнены. Вердикт UI остаётся открытым; «согласовано» не выдаётся.
