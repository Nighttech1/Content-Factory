# memory/ — журнал тикетов агентной команды

Журнал **вне чата Cursor**: что чиним, в каком порядке ролей, какие решения и как откатить.  
Карта команды: [docs/TEAM_ARCHITECTURE.md](../docs/TEAM_ARCHITECTURE.md).

## Зачем

- Контекст чата деградирует; тикеты и цепочки ролей должны жить в файлах.
- Оркестратор зовёт инженеров **только** при наличии `chain.md` у тикета.
- Откат кода — через **git** (`before_sha` / `after_sha` в `decisions.md`); папки тикетов после `done` **не удалять**.

## Жизненный цикл тикета `C-*`

1. **Клиент** создаёт `memory/tickets/C-xx-slug/` из `_templates/`, заполняет `ticket.md`, строку в `_index.md` (`status: open`).
2. **Оркестратор** набирает волну (макс. 3) → пишет `memory/waves/W-yyyy-mm-dd-n.md`, ставит тикетам `in_wave`.
3. **Архитектор** до любого кода пишет в папку тикета `architect-spec.md` + `chain.md` (+ при необходимости обновляет их mid-flight).
4. Инженеры / Тестер / Фиксер / Деплоер идут **строго по `chain.md`**, логируют шаги в `decisions.md`.
5. Закрытие: `guards.md` + строка в regression-guards скилла Клиента → `status: done` в `status.md` и `_index.md`.
6. Откат: `git checkout`/`revert` по `before_sha`; в `status.md` → `rolled_back`; memory сохранить.

## Параллелизм

- Один чат / последовательные роли по `chain.md` — **норма**.
- **Нельзя** двум агентам править один файл/путь из `chain` без merge-плана Архитектора в `architect-spec.md`.
- Параллель только для независимого research (не закрывает `C-*` и не пишет overlapping paths).
