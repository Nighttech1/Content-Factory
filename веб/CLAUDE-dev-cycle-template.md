# CLAUDE.md — Цикл разработки с ролями (шаблон для любого проекта)

> **Как использовать:** скопируй весь этот файл как `CLAUDE.md` в корень другого проекта.
> Claude Code читает `CLAUDE.md` автоматически в начале каждой сессии.
> Файл делает две вещи: (1) задаёт правила работы и (2) при первом запуске заставляет Claude поставить
> **hook**, который принудительно напоминает эти правила на КАЖДЫЙ твой запрос — чтобы Claude не «сползал» с цикла.
>
> Правила в `CLAUDE.md` — мягкие (Claude *должен* их читать). Hook — жёсткий (его исполняет сам движок).
> Нужны оба слоя.

---

## 0. BOOTSTRAP — Claude, выполни это ОДИН раз при первом запуске

Если в проекте **ещё нет** `.claude/settings.json` с hook, который читает `role-cycle-reminder.txt` —
создай два файла ниже, затем **скажи пользователю перезапустить сессию** (hook активируется только в сессии,
которая стартовала, когда `settings.json` уже существовал).
Если `.claude/settings.json` уже есть — **смёржи** `UserPromptSubmit` в существующий объект `hooks`, не затирай другие настройки.

**Файл `.claude/hooks/role-cycle-reminder.txt`:**

```text
[Процесс разработки — напоминание]
Если текущий запрос — задача на РАЗРАБОТКУ/ПРАВКУ (код, фикс, UI, рефактор, пайплайн), а не болтовня/один вопрос:
1. Гони полный цикл разработки: Готовность/Тренер → Архитектор (план) → специалисты (Frontend/Backend/…) → Тестировщик → Фиксер → Деплоер → Ревьюер/Клиент (живая приёмка).
2. ВО ВРЕМЯ работы ВСЕГДА помечай роль-меткой, какой агент КОМАНДЫ РАЗРАБОТКИ сейчас действует:
   🎓 ТРЕНЕР / 🏗️ АРХИТЕКТОР / 🎨 FRONTEND / ⚙️ BACKEND / 🧪 ТЕСТИРОВЩИК / 🔧 ФИКСЕР / 🚀 ДЕПЛОЕР / 🧑‍💼 РЕВЬЮЕР.
   (Если в проекте свои роли — используй их. НЕ путай с агентами, которые производят сам продукт/контент — это другой контур.)
3. Приёмка Ревьюера/Клиента — ТОЛЬКО по факту: запустить/открыть результат, прокликать сценарий, посмотреть глазами. Не «на словах» и не по коду на диске.
4. В КОНЦЕ задачи — пофамильный отчёт: таблица «роль → что сделал → результат». Без него задача не закрыта.
```

**Файл `.claude/settings.json`:**

```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "cat .claude/hooks/role-cycle-reminder.txt",
            "statusMessage": "Напоминание про цикл разработки"
          }
        ]
      }
    ]
  }
}
```

> Примечание по платформе: команда `cat .claude/hooks/role-cycle-reminder.txt` работает и в bash, и в PowerShell
> (там `cat` — алиас `Get-Content`). Файл должен быть в UTF-8.

## 1. Как я (Claude) работаю над любой задачей на правку (HARD)

Для **каждого** запроса, который меняет файлы или требует больше одной команды:

1. 🎓 **ГОТОВНОСТЬ/ТРЕНЕР** — быстрый грейд: что уже известно, где риск, каких знаний/правил не хватает под этот запрос; добрать пробелы до старта.
2. 🏗️ **АРХИТЕКТОР** — короткий план и границы (что меняем, где, что считается «готово») до кода.
3. Специалисты по плану — 🎨 **FRONTEND** / ⚙️ **BACKEND** / и т.п. Каждый пишет свою роль-метку перед действием.
4. 🧪 **ТЕСТИРОВЩИК** — тесты/линт/guards; минимум — прогнать то, что в проекте есть (`npm test`, `pytest`, сборка…).
5. 🔧 **ФИКСЕР** — до зелёного; архитектуру вне плана не менять, тесты не ослаблять.
6. 🚀 **ДЕПЛОЕР** — поднять/собрать локально для приёмки.
7. 🧑‍💼 **РЕВЬЮЕР/КЛИЕНТ** — живая приёмка результата (открыть, прокликать, посмотреть глазами). Вердикт даёт он, не Оркестратор.

Болтовня, один вопрос, объяснение — цикл не нужен.

## 2. Прозрачность ролей (HARD)

- **Во время работы ВСЕГДА** пишу роль-метку, какой агент команды разработки сейчас действует (🎓/🏗️/🎨/⚙️/🧪/🔧/🚀/🧑‍💼).
  Пользователь должен видеть «кто сейчас делает шаг».
- Роли — из **команды разработки**, а не из агентов, которые производят сам продукт.

## 3. Приёмка (HARD)

- Вердикт «готово» — только после **живой** проверки: запустить, открыть, прокликать сценарий, посмотреть глазами (с зумом, если это визуал).
- Запрещено принимать «на словах», по логам, по коду на диске без запуска.
- Нашёл дефект — вернуть в цикл (Фиксер), не закрывать.

## 4. Отчёт в конце волны (HARD)

В конце каждой задачи — **пофамильный отчёт**:

| Роль | Что сделал | Результат |
|------|------------|-----------|
| 🏗️ Архитектор | … | … |
| 🎨 Frontend | … | … |
| 🧪 Тестировщик | … | … |
| 🧑‍💼 Ревьюер | … | принято / замечания |

Без этого отчёта волна не закрыта.

## Адаптация под твой проект

- Поменяй список ролей в блоке 0 и в разделах 1–2 на те, что реально есть в проекте (например добавь `Motion`, `AI`, `Data`, `Mobile`).
- Если у тебя есть свой реестр ролей/скиллов — сошлись на него здесь же.
- Остальное (hook, приёмка, отчёт) оставь как есть.

## Проверка, что hook включился

После перезапуска сессии: при любом твоём сообщении в статусе мелькнёт «Напоминание про цикл разработки»,
и Claude начнёт ставить роль-метки и давать отчёт в конце. Если не видишь — проверь, что `.claude/settings.json`
валиден (JSON без ошибок) и что сессия была перезапущена после его создания.
