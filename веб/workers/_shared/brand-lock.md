# Brand Lock — инварианты визуальных работяг

Цель: **один брендбук = один визуальный язык**. Модель не «украшает», не «улучшает палитру» и не меняет сетку между слайдами одной джобы.

## Источники правды (порядок приоритета)

1. **Загруженный club brandbook MD** (заполненный по [`brandbook.template.md`](./brandbook.template.md))
2. Этот файл (`brand-lock.md`)
3. Токены продукта / Studio UI из корневого `ARCHITECTURE.md` §2.1 — **только для UI приложения**, не для произвольного «вайба» слайдов
4. Вкус модели / «сделай красивее» — **игнорируется**

Конфликт «ARCHITECTURE vs brandbook клуба» на **медиа-слайдах**: побеждает brandbook клуба.  
Конфликт на **экранах Studio/Mesh**: побеждает `ARCHITECTURE.md`.

## Жёсткие запреты (style drift)

| Запрет | Почему |
|--------|--------|
| Менять HEX между слайдами одной джобы | Ломает серию |
| Новые layout / отступы «чтобы влезло» | Ломает grid system |
| Другой шрифт, если в MD уже задан | Glyph / brand mismatch |
| Freestyle градиенты, glow, glass, «нейростиль» без разрешения в §5 brandbook | Шум, не клуб |
| Карточки разной ширины/высоты в одном сете | «Хаотичная витрина» |
| Truncate с `…` / line-clamp, если в spec полный перенос | Читаемость |
| Подмена армянского текста латиницей/кириллицей «для красоты» | Аудитория клуба |
| Игнор `layout system id` / версии brandbook | Невоспроизводимость |

## Обязательные правила для `designer-carousel`

1. **Вход:** topic/script JSON **и** путь к MD brandbook. Без MD → статус `FAILED` / отказ, не «дефолтный красивый шаблон».
2. **Парсинг MD:** извлечь токены, типографику, safe margins, список разрешённых типов слайдов, `brandbook_version`, `layout system id`.
3. **Один layout system** на всю карусель: одинаковые margins, gap, радиусы, позиции лого и номера слайда.
4. **Только разрешённые типы** из §4 brandbook (`cover`, `point`, …). Нет типа в списке — слайд не генерировать.
5. **Canvas:** строго `1080×1350` (4:5), если brandbook не задал иное явно.
6. **Шрифты:** Armenian → `Noto Sans Armenian` (или club font из MD). Не silent-fallback на системный sans.
7. **Реролл одного слайда:** сохранить те же токены и layout; меняется только контент/композиция внутри слотов.
8. **Лог:** в `feedbackLogs` записать `brandbook_version` + `layout_id` + checklist «lock ok».

## Правила для остальных дизайнеров

- `designer-graphics` — те же цветовые/типографические токены; другие форматы холста только если указаны в brandbook.
- `designer-cartoon` / `designer-heygen` — палитра субтитров, end-card и persona берутся из brandbook; нельзя подставить «дефолт HeyGen skin», если указан club persona id.

## HITL

Админ в Inspector может править текст и рероллить слайд, но **не** считается окном для смены brandbook mid-job без явной смены файла/версии.

## Проверка перед отдачей в HITL

- [ ] Все слайды одной высоты/ширины canvas
- [ ] Одинаковые margins / номер / лого-слот
- [ ] Цвета ⊆ таблице токенов
- [ ] Шрифты ⊆ таблице типографики
- [ ] Нет элементов вне safe area
- [ ] `brandbook_version` в логе совпадает с загруженным MD
