## 1. Назначение продукта

**Vernatun Content Factory** — завод контента для армянского клуба Vernatun.

### Целевая модель работы (для аудита и roadmap)

| Кто | Роль |
|-----|------|
| **Завод (агенты)** | Работает **автономно**: смотрит конкурентов, разбирает виральное, пишет сценарии, рисует, кладёт в черновики и очередь |
| **Вы (владелец/админ)** | В основном **только согласовываете выпуск**: апрув черновика, слот в Расписании, «да/нет» предложениям Тренера. Не обязаны писать тексты и собирать макеты руками |
| **Агент-Тренер** | Постоянно предлагает улучшения Сценаристу / Дизайнеру / другим агентам модуля **на основе того, что сработало у конкурентов**; правки в промпты и правила — **только после вашего согласования** |

### Что умеет платформа сегодня

- ленты **конкурентов** и своих **черновиков / опубликованного** по модулям;
- **разбор** чужих каруселей (хук, середина, CTA, виральность) → задания Тренеру и handoff Сценаристу;
- **создание** контента агентами (сценарий → дизайн → черновик → HITL);
- **дизайн-система** (DESIGN.md / brandbook) для отрисовки;
- **расписание** и **аналитика**;
- **Маркетинг-директор** (стратегия, план, порядок выкладки);
- **Команда выпуска** (mesh) — отдельный пайплайн на каждый тип контента.

Роли доступа: **OWNER** (полный доступ, mesh) и **ADMIN** (Studio, инспектор, аналитика).

## 3. Студия — модули (полный список)

Платформа — **мульти-канальный завод**, не только карусели.

### 3.0 Реестр модулей / пайплайнов

**Ядро Studio** (`src/modules/manifests.ts` — плитки на Launchpad):

| # | ID | Что производит |
|---|-----|----------------|
| 1 | `carousel-engine` | Карусели Instagram 4:5 (самый полный UX: Разбор, Create, Доски, drafts) |
| 2 | `aesthetic-graphics` | Полезные картинки и инфографика |
| 3 | `cartoon-reels` | Мульт-рилсы 2D, 9:16 |
| 4 | `heygen-reels` | Рилсы с AI-аватаром HeyGen |
| 5 | `site-articles` | Статьи на сайт |
| 6 | `tg-articles` | Статьи / посты в Telegram |

**Дополнительно в Команде выпуска / mesh** (`lib/mesh-roles.ts`):

| # | ID | Что производит |
|---|-----|----------------|
| 7 | `custom-reels` | Вертикальный рилс (сценарист + монтаж) |
| 8 | `custom-clips-to-reels` | Нарезки длинного видео → короткие рилсы |
| 9 | `custom-info-video` | Информационное видео |

Плюс **plugin slot** — регистрация кастомного модуля через Module SDK (`/api/modules/register`).

У каждого модуля — **своя** команда агентов (не один общий граф на всё).

Зрелость: `carousel-engine` — эталон; остальные модули разделяют UI-паттерны Студии, глубина промптов/рендера разная (зона аудита).

### 3.1 Внутри модуля (`/studio/[moduleId]`)

### 3.2 Колонка «Наши»

- Тумблер **Опубликовано | Черновики** (белый текст).  
- Поиск + сортировка + фильтр.  
- Карточки превью: метрики на фото; у «Наших» **без** плашки ника/подписчиков.  
- Черновики создаются из Create («Нарисовать» / «Опубликовать» → upsert в Черновики).

### 3.3 Колонка «Конкуренты | Доски»

- Сегмент: **Конкуренты** vs **Доски** (имя активной доски на кнопке).  
- Выпадающий список досок из кнопки сегмента: создать, выбрать, **двойной клик = переименовать**.  
- Поиск + сортировка + фильтр; кнопка **загрузки** (иконка) всегда в ряду (на Конкурентах — серая/disabled, на Досках — активна; layout не прыгает).  
- **Конкуренты (live):** Apify Instagram Scraper при ключе; без ключа / ошибке — пусто или (только при `USE_FEED_FIXTURES=1`) демо.  
- Карточка конкурента: чёрная плашка `ник | 182к`, метрики (просмотры / лайки / комментарии / репосты / сохранения), кнопка **Разбор**.  
- **Доски:** свои загруженные кадры/карусели для разбора без метрик «как у IG».

### 3.4 Команда выпуска / Аналитика модуля / Создать

- **Команда выпуска** — экран агентов модуля (flowchart): User/Scout, Разборщик, Сценарист, Дизайнер, Публицист, Analyst, **Тренер**… модели и промпты. Поле «базовый бриф» клиента **убрано** — в чат агентам не подмешивается.  
- **Создать** — модалка Create для карусели (см. §5); аналогичные входы для других модулей по мере зрелости.  
- Аналитика модуля — при наличии роута.

## 4. Разбор конкурента (Razbor)

Модальное окно:

1. Сверху вкладки агентов (4 иконки людей).  
2. Слева чат; справа превью слайдов (крупное, индекс `N/M`, без обрезки).  
3. Старт: короткое приветствие Разборщика → **«Начать разбор»**.  
4. **Live Haiku:** анализ хука / середины / CTA / виральности + **конкретные задания Тренеру** на усиление Сценариста и Дизайнера модуля (чтобы завод учился на конкурентах).  
5. Follow-up в чате опирается на сохранённый анализ (не «я не вижу карусель»).  
6. **Передать сценаристу** — круглая кнопка в блоке ввода; уносит brief + insights.  
7. Модели (карусель): Разборщик и Сценарист — Haiku; Дизайнер — GPT Image.

Скролл/скрин должны ловить **окно**, не фон страницы.

## 5. Создание карусели (Create)

Паритет UI с Разбором, но старт с **Сценариста**:

| Шаг | Что делает пользователь / агент |
|-----|----------------------------------|
| Сценарист | Тема (+ опц. N слайдов, CTA 1–4); STRICT JSON; swipe_trigger = meta «зачем листать» (не на кадр); подсказка «?» по типам CTA |
| Передать | Handoff дизайнеру |
| Дизайнер | Описание → **Нарисовать** (панорама→нарезка 4:5, цвета из Settings Design) |
| Превью | Только нарезанные слайды; затем Черновики / Расписание |

Цвета дизайна берутся из **активного** слота Settings → Дизайн; разметку придумывает модель.

## 6. Настройки

### 6.1 Агенты / LLM

Назначение моделей агентам (каталог + custom aggregator ids). Дефолты карусели: Сценарист Haiku+thinking, Дизайнер GPT Image 2.x.

### 6.2 Дизайн (библиотека ≤10)

- Горизонтальные **brandbook-карточки** (цвета, шрифты, кнопки, бары, иконки) — визуал DESIGN.md / preset.  
- Активный слот — **синий неон** по периметру.  
- Кнопки справа сверху: дизайн.md · референс · новый дизайн · **код дизайн мд**.  
- Upload референса → deconstruct (vision/LLM) → новый слот.  
- Кликом выбирается активный дизайн (без отдельного тяжёлого context-редактора).  
- Active sync на сервер для Brand Kit / draw.

## 7. Маркетинг-директор (`/marketing`)

- Слева **проекты** (как папки в ChatGPT) — чаты в одном смысловом проекте.  
- Центр: приветствие + ввод; после первого сообщения поле уходит вниз, идёт диалог.  
- LLM: Haiku; инструменты поиска по данным приложения (модули / черновики / schedule — soft-fail).  
- Сценарии: контент-стратегия, календарь, порядок выкладки.

## 8. Расписание

- Календарь слотов публикации.  
- Список модулей и постов «готовы к публикации» с датой/временем.  
- Публикация в соцсети — только после HITL (не автопуш в обход апрува).

## 11. Сценарии (сквозные)

### Для владельца (целевая автономия)

1. Завод сам наполняет черновики по модулям → вы открываете **Расписание / Инспектор** → **согласовываете выпуск**.  
2. Тренер приносит список улучшений агентов после разборов → вы **согласовываете** правки промптов.  
3. Директор предлагает контент-план → вы **утверждаете** календарь.

### Ручные / гибридные (как часто пользуются сейчас)

1. **Разведка:** Студия → модуль → Конкуренты → Разбор → Начать разбор → передать Сценаристу → Создать.  
2. **С нуля:** Создать → Сценарист → Дизайнер → Черновики → Расписание.  
3. **Бренд:** Настройки → Дизайн → активный brandbook → draw.  
4. **Стратегия:** Директор → проект → план.  
5. **Доски:** свои референсы → Разбор без Apify.  
6. **Другой модуль:** Launchpad → рилсы / статьи / графика → своя команда выпуска.

## 11.1 Агент-Тренер (выпуск) — функционал

| Шаг | Поведение |
|-----|-----------|
| Вход | Разборы конкурентов, метрики, провалы собственных черновиков |
| Выход | Нумерованные задачи: «Сценаристу — усилить hook bar…», «Дизайнеру — seamless bridges…» |
| Согласование | Владелец видит предложение и **одобряет / отклоняет / правит** |
| Эффект | Обновляются system prompts / rules / skills агентов **этого модуля** (и при необходимости общие каноны) |
| Цель | Завод становится сильнее именно там, где конкуренты уже доказали виральность |

Отличие от Тренера разработки (Cursor): тот учит **команду разработки UI/кода**; этот — **агентов производства контента** внутри платформы.

## 12. Ограничения и известные пробелы (для аудита «что улучшить»)

| Область | Сейчас | Возможные улучшения |
|---------|--------|---------------------|
| Автономия завода | Карусель-конвейер сильный; полный «сам нашёл → сам в очередь» ещё гибридный | Закрыть цикл без ручного Create на всех 9 пайплайнах |
| Тренер выпуска | Задачи из Razbor + memory notes; согласование с вами — канон | UI «очередь улучшений агентов» с one-click approve |
| Live конкуренты | Apify + кэш; при ошибке пусто | Дешевле лимит / ручной URL / бюджет-алерт |
| Черновики / boards / design | Часто localStorage | Синк в Postgres |
| Модули 2–9 | Есть в mesh/Studio; глубина разная | Паритет с carousel-engine |
| Публикация | HITL-очередь | Автопостинг только после вашего апрува |
| Стоимость LLM+Apify | Кэш 30м, лимит runs/час | Дашборд spend |
