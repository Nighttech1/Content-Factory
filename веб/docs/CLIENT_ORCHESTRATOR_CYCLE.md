# Цикл Клиент ↔ Оркестратор (обязательный)

Источник правды для запуска из чата. Короткая команда — в файле `promts` и в `.cursor/prompts/start-client-orchestrator-cycle.md`.
Читать целиком перед стартом. Knowledge — универсальная `knowledge/` + домен `knowledge/area_content_factory/`. Источники продукта: `ARCHITECTURE.md`, `DEV_PLAN.md`.

Цикл **не завершён**, пока одновременно:

1. все тикеты Клиента `C-*` закрыты с **guard**;
2. Клиент явно написал слово **«согласовано»** в финальном отчёте пользователю.

Роли: **Клиент** и **Оркестратор** (**Тренер** = шаг 0 волны: грейд готовности → Архитектор → специалисты → Тестировщик → Фиксер → Деплоер). Контуры не смешивать.

Используй полную библиотеку `.cursor/skills/`, `.cursor/mcp.json`, `plugins/`, `knowledge/`. Доменные skills фабрики обязательны по задачам DEV_PLAN (см. `.cursor/registry/agents.md`). Новые агенты из реестра входят в команду Оркестратора.

---

## Лимиты

| Кто | За один прогон |
|-----|----------------|
| **Клиент** | любое число тикетов `C-*` |
| **Оркестратор** | по умолчанию **≤3 тикета** в одной волне (фокус), без overlapping paths |

Лимит **3 не жёсткий.** Если пользователь явно просит «до конца» / «весь бэклог» / «снять лимит» / «одним проходом» — Оркестратор берёт **всю очередь волны** без разрезания на пачки по 3.

---

## ФАЗА A — КЛИЕНТ

`client.mdc` + client-review / visual-critic / ticket-engine из `.cursor/skills/` + оболочка `knowledge/engineering/roles/client.md`.

1. Смотри живой localhost (не только файлы на диске). Visual — скрины MCP / image-diff.
2. Выдай любое число `C-*` в `memory/tickets/` + `_index.md`.
3. Сразу передай управление Оркестратору. Не останавливайся на списке тикетов.

---

## ФАЗА B — ОРКЕСТРАТОР (волна: ≤3 по умолчанию; full queue по явному запросу)

1. **Тренер (шаг 0):** `memory/trainer/YYYY-MM-DD-grade.md` — грейд A–D; при C/D закрыть пробелы skills/rules до кода.
2. `memory/waves/W-*.md`, `before_sha`. Зафиксируй режим: default ≤3 **или** full-queue (если пользователь снял лимит).
3. Архитектор: spec + `chain.md` **до кода**.
4. Специалисты по chain (Frontend / Motion / WebGL / Backend / новые агенты из реестра).
5. Тестер + guard; Фиксер до зелёного; Деплоер localhost.
6. Закрытие только с guard. В режиме ≤3 — стоп «готов продолжить». В режиме full-queue — продолжай, пока очередь волны не пуста.

После «не то»: снова Тренер (gap) → усиление файлов → повтор с п.3.

---

## ФАЗА C — ПОВТОР

Снова Клиент. Пока очередь не пуста и нет слова **«согласовано»**.
