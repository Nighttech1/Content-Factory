# Спецификация: видеомонтаж и библиотека референсов

Статус: **проектирование** · Область: custom-reels / custom-clips-to-reels и carousel-engine.

## Подтверждённое текущее состояние

### Рилсы

- В `custom-reels` UI уже есть `ReelsFrameworkPanel`: он позволяет создать reel-job, загрузить видео, запросить рендер и отправить текстовую правку.
- `POST /api/reels/[reelId]/sources` принимает один MP4/MOV/WebM/M4V за запрос в папку задачи (лимит `REELS_MAX_SOURCE_MB`, по умолчанию 512 MB) и хранит метаданные/sha256.
- Отдельный `POST /api/reels/[reelId]/analyze` читает метаданные, считает эвристический `takeScore`; распознавание зависит от настроенного `WHISPER_BASE_URL`. Текущая кнопка рендера в панели не вызывает analyze перед ним.
- `buildSimpleMontageFromSources` создаёт сцены из каждого загруженного файла начиная с 0 и обрезает до 12 секунд на файл; для дефолтного `professional` профиля creative director сокращает такой клип примерно до 6 секунд. Это техническая нарезка начала файла, не поиск лучших смысловых моментов в длинной записи.
- В текущем простом плане subtitle cue берёт название темы (имя файла — fallback) на первые секунды клипа. Он не транскрибирует речь.
- `renderMontageWithFfmpeg` собирает JSON-монтаж в MP4 1080×1920, если доступен FFmpeg. Subtitle pass сейчас рисует лишь первые 12 cues обычным `drawtext` в одной нижней позиции; стиль профиля к ним полноценно не привязан.
- `CapCutEditorShell.tsx` содержит `MOCK_LAYERS` и `MOCK_CLIPS`; это визуальная оболочка, а не подключённый интерактивный редактор реального монтажа.

**Вывод:** в приложении можно загрузить видео и получить базовый FFmpeg-экспорт; локально в этой среде `ffmpeg`/`ffprobe` присутствуют, но `WHISPER_BASE_URL` не настроен. Сейчас нельзя обещать «загрузил длинную запись — ИИ нашёл лучшие моменты, распознал речь и сделал стильные точные субтитры». Между upload/render и этим сценарием нужны анализ с выбором клипов, редактируемая транскрипция, caption renderer и референсная библиотека.

### Карусели и визуальные примеры

- Текущая генерация принимает пользовательские вложения как job-level assets (`ingestUserAssets`); это материалы для конкретного выпуска.
- Settings → Design deconstructor принимает изображения, выделяет дизайн-пресет и сохраняет эталон в Design library; лимит и storage связаны с preset library.
- Boards предназначены для референсов и серверное хранилище уже существует, но нет подтверждённой общей typed-библиотеки cross-format «рилсы + карусели» с правами, тэгами, стабильным ID и явным выбором на новый job.

## Цель продукта

Пользователь может отдельно хранить исходные материалы, брендовые ресурсы и стилевые референсы. В каждом новом задании он выбирает один или несколько сохранённых референсов либо загружает новый. Агент извлекает визуальную/монтажную грамматику, связывает её ID с job и переносит на новые материалы под бренд Вернатуна. Референс никогда не попадает в output автоматически.

## Модель библиотеки

Единица `MediaReference` должна иметь: стабильный `id`; `projectId`; `kind` (`reel_style` | `carousel_style`); имя; MIME/размер/длительность/размеры; hash; внешний `storageKey`; thumbnail/poster; автора/URL источника; статус прав (`unknown` по умолчанию, `licensed`, `owned`, `restricted`); теги; пользовательские заметки; извлечённый style profile; `createdAt`, `updatedAt`, `archivedAt`.

Большой бинарник — только объектное хранилище, не Git/DB blob. Метаданные и связи с job — БД. Повторная загрузка одинакового хеша предлагает использовать существующий объект. Удаление из библиотеки не удаляет исходник, draft или уже собранный экспорт без отдельного подтверждения.

`JobReference` связывает `jobId`, `referenceId`, роль (`primary_style` | `secondary_style`), короткую задачу пользователя и профиль, зафиксированный на момент запуска. Сохраняй этот snapshot, чтобы повтор рендера не менялся после редактирования reference.

### Форматы

- Reel style: MP4, MOV, WebM, M4V; лимиты проверять конфигом/планом, не хранить в source list целевого ролика.
- Carousel style: PNG, JPG, WebP; отдельные страницы или упорядоченная сетка до согласованного лимита.
- Upload job footage и upload style reference — разные API-поля и разные таблицы/папки.
- Проверять MIME и фактический codec/container по содержимому; безопасно извлекать metadata/poster; ограничивать размер/длительность; не исполнять загруженный файл.

## Анализ референсов

### Рилс

Сохраняемый разбор: длина/формат; тип хука и момент появления; кадровый ритм; типы планов; позиции и длина caption lines; акцентирование; переходы/титры; баланс речи/музыки; CTA. Анализ должен возвращать наблюдения с таймкодами, уровень уверенности и рекомендации, не полный transcript чужого ролика.

При обработке source footage сформировать shortlist с source in/out, фразой/действием и обоснованием. Каждый финальный клип ссылается на точный исходник/таймкоды. Никакой автосклейки референсного ролика в итог.

### Карусель

Разбор: число/формат слайдов; обложка → основной ритм → CTA; композиция и safe zones; палитра/типографика; повторяющиеся графические элементы; bridge между слайдами. Хранить design grammar/`layoutMap`, а не копию чужих текстов/картинок.

## Субтитры и монтажный план

- Генерировать cue-level timestamps из распознавания; если доступны только сегменты, не изображать точность word-level.
- Оставлять транскрипцию редактируемой; поддерживать RU/HY, Unicode-safe шрифт и ручное подтверждение сомнительных армянских слов/имён.
- Стили: минимум `clean`, `bold`, `karaoke` с позициями, safe zones, акцентом/анимацией; каждый cue ограничен по длине, без перекрытия и выхода за длительность клипа.
- Превью и `.srt`/sidecar плюс burn-in экспорт; пользователь выбирает стиль, профиль получает устойчивый ID.
- MontageProject версионируется; timeline UI управляет существующим Zod-контрактом, не создаёт параллельную модель; render идёт асинхронно с реальным прогрессом.
- До экспорта показать монтажный список с таймкодами; разрешить пользователю исключить/подвинуть фрагмент, исправить transcript и изменить captions.

## Минимальный UI

Без редизайна shell: добавить в существующие разделы References и Drafts компактную полку референсов с фильтрами по типу/тегу, кнопкой загрузки, preview и статусом прав. В drawer создания рилса/карусели показать выбор существующих references и отдельную загрузку нового reference. На карточке драфта показывать `reference_id`, применённые признаки и метку «стиль адаптирован».

## Безопасность и бренд

- Разрешён стиль/монтажная грамматика. Чужие исходные кадры, речь, текст, музыка, логотип, лицо/сходство и уникальные иллюстрации не использовать повторно без явного разрешения/подтверждённых прав.
- `unknown` права означают «только анализ стиля», не право переиспользовать материал.
- Активный бренд Вернатуна главнее reference; не переносить чужой бренд/watermark.
- Не публиковать автоматически; сохранять редакторский и human approval gates.
- Пользовательские исходники и references — zero data loss: отдельное удаление с явным подтверждением, no destructive cleanup.

## Приёмка будущей реализации

1. Отдельная загрузка source footage и style reference; референс не попадает в timeline/input ролика автоматически.
2. После обновления страницы и открытия проекта в другом браузере/профиле выбранные references доступны по stable ID согласно правам доступа.
3. Пользователь видит таймкоды и может принять/отклонить каждый выделенный клип до сборки.
4. Whisper отсутствует/недоступен — понятный статус и ручной путь, без фиктивного transcript.
5. RU/HY captions проходят визуальную проверку safe zone/шрифта; рендер отчитывается о реальном FFmpeg result.
6. Reference notes, права, теги и применённый job snapshot видны в asset history.
7. Карусель может использовать загруженный style reference в разных jobs, при этом user photos остаются отдельными source assets.
8. Удаление записи не уничтожает job footage или уже созданные drafts; публикация всё ещё закрыта human approval.

## Порядок реализации

1. Архитектор сверяет storage/Prisma/Boards/DesignPreset contracts и предлагает additive migration + API.
2. AI Bridge фиксирует typed `reference_id`/analysis contract, transcription cues и no-clone limits.
3. Backend добавляет библиотеку/связи, storage и lifecycle guards.
4. Frontend добавляет только компактный picker/upload/preview в существующий shell; редактор подключается к MontageProject вместо mock layers.
5. Motion/Backend реализуют caption presets и render/preview/sidecar.
6. Tester проверяет upload, persistence, rights states, timecodes, output and no data loss; Клиент принимает живой сценарий.
