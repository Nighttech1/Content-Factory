## Распределение работы

| Роль | Ответственность следующей волны | Доказательство |
|---|---|---|
| Клиент | Уточнить результат из правок владельца, сценарии и замечания | C-* с ожидаемым поведением; финальная живая приёмка |
| Оркестратор | Сверить ветки, версии и зависимости; вести волну | before_sha, scope, chain, перечень изменённых файлов |
| Тренер | Проверить готовность ролей и средств проверки под конкретную задачу | Грейд и закрытые пробелы до кода |
| Архитектор | Определить перенос в main и минимальный набор изменений | Spec, контракты, сохранность данных, порядок проверок |
| Frontend | Правки доски, карточек и адаптивности | Изменения в существующем UI, без второго продукта |
| Motion | Подключать при изменении анимаций | Проверка жестов, скролла и reduced motion |
| Backend | API, права, сохранение и конфликты | Проверки контрактов и доступа |
| AI Bridge | Подключать при изменении передачи заданий/данных | Прослеживаемый импорт и подтверждённый транспорт |
| Тестировщик | Проверить затронутые сценарии и регрессии | Команды, результаты, guard для каждого исправления |
| Фиксер | Исправить найденные дефекты | Повтор затронутых проверок |
| Деплоер | Подготовить проверенный артефакт и выпуск | SHA, QA run, hash артефакта, backup, rollback |
| Клиент | Проверить результат на desktop/mobile | Сценарии кликов и снимки; автор кода не выдаётся за независимого проверяющего |

Неприменимые роли отмечаются как пропущенные с причиной. Не сообщать, что все роли уже исполнили новую волну.
По умолчанию до трёх тикетов за волну; при явном поручении пройти всю очередь — полный объём.

- [ ] Подготовленные материалы и контент-план не теряют ID и не дублируются.
- [ ] Проверить desktop 1440 и mobile 390/360: клавиатуру, touch/scroll, отсутствие overflow, армянские глифы, ошибки консоли.
- [ ] Runtime QA выполняется с временными данными; реальные публикации и платные API не вызываются ради проверки.
- [ ] Клиент принимает живые сценарии; HTTP 200 и успешная сборка не заменяют приёмку.
- [ ] Для нового SHA получен новый успешный QA и совпадающий неизменяемый артефакт.
- [ ] Перед prod подтверждены доступ, место, backup, откат и действующее поручение на выпуск.

## Предусловия нового выпуска

1. Workflow сейчас запускается только на codex/director-chatgpt-transfer при изменении одного QA/release marker. Коммит в main сам по себе его не запускает.
2. Если переносим выпуск в main, согласованно обновить workflow, gate, prepare helper и их тесты; не ослаблять проверки SHA/artifact/backup ради миграции.
3. scripts/prepare-growth-release.mjs содержит старое имя Nighttech1/Content-Factory: до использования с новым origin исправить совместимость и прогнать scripts/test-prepare-growth-release.mjs.
4. Общий веб/.claude/skills/deployer/SKILL.md содержит legacy Sputnik/Flutter/чужой VPS. Не использовать его адрес или команды для этого продукта. Текущий контекст — таблица выше и scripts/deploy-growth-center.sh.
5. Runtime-инвентаризация использует старые диагностические признаки noDropIns/execPathNode: их false при управляемом standalone drop-in не означает поломку. Действующий deploy adapter проверяет точный разрешённый drop-in; не обходить его.
6. Новый релиз: backup → неизменяемый проверенный bundle → атомарный current → health/revision/routes → rollback при ошибке. Общие данные и медиа не затирать; не выполнять reset БД.
7. Подготовка команды не является разрешением на публикацию контента, расходы API или новый prod deploy.
